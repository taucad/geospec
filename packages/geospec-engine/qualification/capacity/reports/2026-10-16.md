# CAP-0 capacity qualification, 2026-10-16

This is the first full-scale run of the CAP-0 harness on branch `lane/capacity-qual`, which starts from the head of pull request 40 with host-selected engine limits merged. The harness admits procedurally generated closed meshes into the backend-free core engine and runs bounding box, watertight, connected components and volume claims. It records bytes, counts, peak RSS, wall time, work units and an outcome class for each claim under each limits profile.

The run covers the glTF and GLB mesh route only. The OCCT bridge could not be built in this container, so STEP, BRep, AP242, PMI and feature-inventory routes were not measured.

## Reproduce

```bash
pnpm nx run geospec-engine:test-capacity
pnpm nx run geospec-engine:qualify-capacity -- --timeout-s 600 --memory-gib 10
```

The runner builds `bench/capacity`, generates one fixture at a time into a temporary directory, runs one probe process per claim and deletes the fixture before the next. The main run took 82 minutes on four CPUs with 16 GiB of memory. Peak temporary disk was 131 MiB, the closure fixture.

## Hard assertions

All hard assertions held in the main run and in the supplementary runs:

- every refusal carried a typed code: `limit-exceeded` at admission and on plans, or `GEOSPEC_ANALYSIS_LIMIT`, `MATCHER_TIMEOUT` or `GEOSPEC_INVALID_EVIDENCE` on claims;
- no decided verdict contradicted the known truth of its claim;
- under the entry profile every glTF admission crossing refused at admission with `limit-exceeded`;
- each injected admission limit refused one below the measured value and admitted at and one above it;
- decided verdicts agreed across profiles and between each partitioned fixture and its monolithic form.

These assertions establish that the engine fails closed at this scale. They do not establish that it scales: the capacity outcomes below are measurements.

## Findings

1. Admission gates. The primary, per-resource, closure, vertex, triangle and retained-subject limits apply to glTF and GLB admission exactly as configured, with one-byte or one-count precision. With raised host limits every large fixture was admitted in at most 0.35 s at 70 to 240 MiB peak RSS.
2. Occurrence limit. `maxOccurrences` (65,536) is read only from STEP admission facts in `runtime.rs` and `subject.rs`. A glTF subject with 70,000 occurrences is admitted under the entry profile, and its bounding box, watertight and volume claims decide with exact expected values. The limit is not host-selectable.
3. Cheap claims scale. On 4,200,000 triangles bounding box took 0.06 s, volume 0.18 s and watertight 2.7 s at 566 MiB peak RSS. Instanced geometry is charged per occurrence: the 100-instance fixture charged the same 14,700,000 work units as the unique one and its watertight claim used 599 MiB.
4. The default work allowance is a model-size ceiling. These mesh claims charge seven units per occurrence vertex, so the default 8,000,000-unit budget refuses every claim above about 1,140,000 vertices with `MATCHER_TIMEOUT`, even when the host raises every admission limit. The refusal arrives before any analysis and is typed, but a host must raise `workUnitBudget` together with its admission limits.
5. Connected components is the capacity wall. The claim runs exact material classification. Under the entry profile it refuses with `GEOSPEC_ANALYSIS_LIMIT` once the material scratch exceeds 256 MiB, or with `MATCHER_TIMEOUT` when the up-front triangle charge exceeds the budget, as on the 323,640-triangle geode in 2.7 s. With raised limits no fixture above 150,000 triangles finished within the 600 s probe limit; the 147,456-triangle monolithic fixture took 412 s and 13,027,286 units. The probes stopped at 600 s held 1.7 to 2.0 GiB for 3.8 to 4.2 million triangles.
6. The geode reproduction decides when provisioned. In an extended run without the 600 s limit, connected components on the 323,640-triangle, two-component voxel mesh passed in 887 s with 31,716,261 work units and 153 MiB peak RSS. The entry profile refuses the same claim in 2.7 s with `MATCHER_TIMEOUT`, so the model needs about four times the default work allowance and a quarter hour of wall time, not more memory.
7. Pair scratch grows with the square of the shell count. With raised limits the 65,537-shell fixture needed 12.5 GiB of pair scratch and the 70,000-shell fixture 14.2 GiB, a ratio that matches the square of the shell ratio. Both refused only after about five minutes and 80 million units, because the pair scratch is reserved after the shells are built.
8. Mesh entries are a live-analysis ceiling. A plan that demands connected components on 300 subjects is refused whole with `limit-exceeded` ("Prepared connected-component demands need 257 entries; the analysis entry limit is 256"). Its 600 bounding-box and watertight claims, which need no material analysis, are refused with it. `maxMeshEntries` is not host-selectable, so no host profile can lift this.
9. Retention accounting. The small torus needs exactly 804,559 bytes of analysis retention for connected components; one byte less refuses with `GEOSPEC_ANALYSIS_LIMIT`. Bounding box, watertight and volume decide with a one-byte retention limit, so the 566 MiB watertight working set on 4.2 million triangles is outside `maxMeshBytes` accounting.
10. Partition boundaries. A closed torus split into two primitives in two resources, joined only by equal boundary positions, passes watertight and volume but connected components refuses it with `GEOSPEC_INVALID_EVIDENCE` ("Material shells require exactly two oppositely directed triangles per exact edge"). The monolithic form decides correctly. A valid shell that spans primitives is classified as malformed input, which would misreport partitioned or file-backed delivery.
11. Interference across resources. A 32-cube assembly whose only overlapping pair sits in the last resource gives the same component-interference failure and the same 31 spatially connected components in its partitioned and monolithic forms.

## Not run, and why

- NAPI, OCCT and every STEP or BRep route: the OCCT source download is blocked in this container, so no native addon exists. Only the Rust core crate was built.
- The file-backed model above 512 MiB: the artifact route is not available on this branch. The largest closure measured is 131 MiB in five resources.
- Cache disabled and forced-eviction equivalence: the engine has no host switch for either. Only undersized retention was compared, and it refused instead of disagreeing.
- 256 solid entries: they belong to the CSG and BRep routes.
- Connected components at full scale: the main run stops each probe at 600 s. In the extended run the claim on 4,200,000 unique triangles had not finished after 1,800 s; its resident set reached 1.9 GiB within ten minutes and stayed there.

## Engine hooks the harness needs

These are recorded for the engine owner; this lane did not change engine source.

1. Host-selectable `maxOccurrences`, `maxMeshEntries` and `maxSolidEntries` in `runtime/limits.rs`, so their boundaries can be injected below, at and above.
2. Work units charged per claim in each claim result. The engine-wide `logical.chargedUnits` observation is the only work count a host can read, so the harness runs one claim per process.
3. A host control that disables the analysis cache or forces eviction, for the equivalence comparison of test 7.
4. Cooperative cancellation and progress in the core `Engine` API. The runner can only kill a probe.
5. Reserving material pair scratch as soon as the shell count is known, so a quadratic demand refuses before minutes of work.
6. Material classification across glTF primitive boundaries, or a capacity or unsupported refusal instead of invalid evidence.
