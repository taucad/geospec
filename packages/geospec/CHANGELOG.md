## 0.5.0 (2026-10-26)

### 🚀 Features

- `geospec` ships the `geospec` bin. `geospec run` reads the project's `geospec.config.*` (or `--config <path>`): its `include`, `exclude`, `testNamePattern`, `testTimeout` and `bail` apply unless a flag replaces them, and each pool worker imports the config for its `exporters`. `geospec/runner/node` adds `createGeoSpecNodePoolRunner` (with `configPath` and `exporterModules`) and `createNodeGeoSpecEngine`, which runs on the `geospec-engine` native addon when this platform has one and on its WASM build when none is installed; an installed addon that fails to load throws. `geospec/cli` exports `runGeoSpecCli` and `createNodeGeoSpecCliHost` for hosts that wrap the CLI. `geospec` now depends on `geospec-engine`. ([#103](https://github.com/taucad/geospec/pull/103))

  `@taucad/geospec-engine` becomes a compatibility package until it is removed: its bin is renamed `tau-geospec`, so it no longer clashes with `geospec`'s own, and it and `createGeoSpecNativeNodePoolRunner` run `geospec`'s CLI and pool with Tau's default exporter ahead of the config's exporters.

- `geospec/vitest/node` exports `setupGeoSpecVitestProject()`, which reads the project's `geospec.config.*` (exporters and `testTimeout`, with programmatic overrides), builds the model loader and installs the GeoSpec matchers for a Vitest project. The authoring skill says models load through the exporter the host or the project's `geospec.config.ts` supplies, which on Tau projects is Tau's runtime. ([#103](https://github.com/taucad/geospec/pull/103))

  `@taucad/host`'s `test_model` reads the project's `geospec.config.*` and applies its include, exclude, testNamePattern, testTimeout and bail as defaults that an input field replaces; the result's `config` names the file, or reports `GEOSPEC_CONFIG_NOT_APPLIED` once per session. The trust prompt for relayed projects names both `tau.config.*` and `geospec.config.*`.

  `@taucad/mcp`'s `test_model` result schema carries the same optional `config` field, and its description says the config sets defaults.

- `geospec/config` adds `defineConfig`, the `exporters` field and `readGeoSpecConfig`, and drops `cache`, `cacheDirectory`, `subjects` and `GeoSpecTauProjectDescriptor` with the `@taucad/project-core` dependency. `readGeoSpecConfig({ filesystem, projectPath })` reads a config's data fields through the spec VM on any host: a config that imports a package other than `geospec/config` is `not-applied` with reason `unresolved-import`, detected before bundling with no network call. `loadGeoSpecConfig` resolves a config's `geospec/config` import to its own copy when the project has no install. `commandExporter` takes an optional `exportTimeout` and fails an export that runs longer with `GEOSPEC_EXPORTER_FAILED`. ([#103](https://github.com/taucad/geospec/pull/103))
- The compiled GeoSpec engine now comes from npm as `geospec-engine`, published from [taucad/geospec](https://github.com/taucad/geospec), and no longer from the workspace package `@taucad/geospec-engine-native`. ([#103](https://github.com/taucad/geospec/pull/103))

  - `@taucad/geospec-engine` depends on `geospec-engine` and its Node worker pool imports `geospec-engine/node`.
  - `@taucad/host`'s optional GeoSpec peer is `geospec-engine` (`^0.1.0-next.19`); the `test_model` tool is advertised when `geospec-engine/node` resolves.
  - `geospec` documentation points at the `geospec-engine` package.

- Run on `geospec-engine` 0.2.0 and use its host-selected limits. ([#103](https://github.com/taucad/geospec/pull/103))

  - `@taucad/host` constructs its native GeoSpec engine with 1 GiB of analysis memory per subject, so watertight and connected-component claims decide on meshes up to the 4 million triangles the entry admission limit admits. Admission limits stay at the entry profile. The optional `geospec-engine` peer is now `^0.2.0`.
  - `geospec` accepts the `geospec-host-config-v1-…` configuration profile an engine reports when a host selects its limits.
  - `geospec` recognizes the retained-subject refusal by its structured capacity instead of its message, so eviction and re-admission keep working on 0.2.0.
  - A minimum-distance query refused by an analysis or admission limit now returns `analysis-limit` or `resource-limit` instead of an `engine-error` interruption.

- The bundled engine moves to `geospec-engine` 0.4.0. In this version a claim whose expectation has an unknown or malformed field is refused on its own with `GEOSPEC_INVALID_EXPECTATION`, and the other claims in the plan still run. Before, the engine rejected the whole plan with `ProtocolError` `invalid-claim`. The refused claim's diagnostic keeps the former message, and its `details` carry `field` and, when that key occurs once in the payload, its `path`. ([#103](https://github.com/taucad/geospec/pull/103))

  A GeoSpec test whose only undecided claim is such a refusal is `inconclusive`, never passed, so `geospec run` exits 1 and the run is not green. A claim decided false beside it still fails the test. `client.query` returns a malformed query payload as that query's `refused` report instead of rejecting it. Code that caught `invalid-claim` for a malformed payload should read the refused report's first diagnostic instead. A negated query, an unadmitted subject, an out-of-range budget and other plan-level errors still throw `invalid-claim`.

  `test_model` reports such a row with the new failure category `invalid-expectation`, which `@taucad/mcp` advertises and validates in its output schema. The row's suggestion says to correct the expectation to the matcher's documented fields and to keep the assertion. The `geospec-authoring` skill says so.

  `@taucad/host` now asks for the `geospec-engine` peer at `^0.4.0`, the first release that refuses a malformed expectation per claim.

- `geospec` builds, tests and publishes from taucad/geospec, beside the engine it runs. It joins the engine's fixed release group, so every `geospec` version depends exactly on the `geospec-engine` version of the same number and publishes on the same runs. Its public API and CLI are unchanged by the move. The `geospec-authoring` skill bundle under `agent/` keeps its format and is generated in this repository from the package's own declarations, so it carries the package version and the reworded API documentation. ([#103](https://github.com/taucad/geospec/pull/103))
- Add the GeoSpec-native model exporter seam beside the runtime routes: `GeoSpecModelExporter` with declared capabilities, `exporters` on `createModelLoader` and the native model loader (consulted when no runtime is configured), the typed refusals `GEOSPEC_EXPORTER_UNSUPPORTED`, `GEOSPEC_EXPORTER_MISSING`, `GEOSPEC_EXPORTER_FAILED` and `GEOSPEC_EXPORTER_INVALID_ARTIFACT`, and `commandExporter` in the new `geospec/model/node` subpath, which runs any command speaking subprocess protocol 1. ([#103](https://github.com/taucad/geospec/pull/103))
- The bundled engine moves to `geospec-engine` 0.3.0, in which `inspectGeometry`, `analyzeMeshOverlap` and `analyzeBrep` answer `refused` instead of `failed` when the evidence they read is missing or cannot decide: a selector that is unmatched, ambiguous or unsupported on the subject, an inconclusive component partition, an invalid component, a subject with no BRep or a BRep the backend cannot measure. ([#103](https://github.com/taucad/geospec/pull/103))

  Each keeps its diagnostic code, and a refused result carries no `evidence`. A query asserts nothing, so every query now answers `passed` or `refused`; code that branched on `failed` for these queries should branch on `refused` and read the first diagnostic's code. The `client.query` and `evaluateGeoSpecNativeQuery` documentation and the `geospec-authoring` skill say so.

  `@taucad/host` now asks for the `geospec-engine` peer at `^0.3.0`, the first stable release that refuses these queries.

- Add `geospec/runner/node` with `createNodeVmFileSystem` and `resolveUnderRoot`, the Node project filesystem moved from `@taucad/geospec-engine`. `@taucad/geospec-engine/node-filesystem` re-exports it until the package is removed. ([#103](https://github.com/taucad/geospec/pull/103))
- Move the worker pool into `geospec/runner/worker`: `createGeoSpecPoolRunner`, `startGeoSpecPoolWorkerHost` and their option and timing types are exported there, and the pool runs each file through the same `executeGeoSpecFile` step as the serial runner. Remove the forensic timing channel and the matcher wall backstop: the `forensic` and `matcherWallBackstop` run options, config fields and pool messages, the `forensic` runner event and `GeoSpecForensicEvent`, and the `geospec run --forensic` and `--matcher-wall-backstop` flags. A config file that still sets either field is refused as an unsupported field. ([#103](https://github.com/taucad/geospec/pull/103))
- `geospec` depends on no Tau package (D11): it drops `@taucad/runtime` and `@taucad/esbuild` and bundles specs with plain `esbuild`. `runGeoSpecModule`, `readGeoSpecConfig` and the runner options (`GeoSpecRunnerOptions`, the native runner, the pool worker host) take an optional `createModuleVm`; the Node pool runner and `createNodeGeoSpecCliHost` take `moduleVmModule`, the URL of a module whose default export is that factory. ([#103](https://github.com/taucad/geospec/pull/103))

  `geospec/runner` exports the `ModuleVm`, `CreateModuleVm`, `GeoSpecModuleVmModule`, `VmFileSystem`, `VmIssue`, `BundleResult` and `BuiltinModule` types and `createPlainModuleVm`, the default: native esbuild on Node over project files and the GeoSpec builtins. A spec or config that imports an npm package or URL on the default refuses with `BUNDLER_FAILED` naming the specifier, and nothing is fetched; outside Node every bundle refuses until a host injects a VM. Tau's hosts inject Tau's esbuild VM, so a spec run through Tau resolves packages as before.

- Load Tau models through a host exporter instead of a runtime client. The `runtime` model-loader option, `GeoSpecRuntimeClient`, the runtime export-intent helpers and `exportTauProjectArtifact` leave `geospec`; Tau hosts now pass `exporters: [await tauClientExporter({ client })]` from `@taucad/agent-tools/geospec`, which claims the extensions the client's kernels declare. `HostGeoSpecRuntimeClient` in `@taucad/host` now names the Tau runtime surface the exporter uses instead of GeoSpec's client, and `createHostGeoSpecRunner` takes any Tau runtime client. The engine's pool worker exports through the same exporter over its default runtime. ([#103](https://github.com/taucad/geospec/pull/103))
- Report each GeoSpec limit refusal as a typed limit, and a refused load as an inconclusive test instead of a failed one. ([#103](https://github.com/taucad/geospec/pull/103))

  - A `test_model` failure or test row refused by a limit carries `limit`: its `kind` (`capacity` or `budget`), `name`, `declared` and `measured` values in `unit`, the refused `operation` and `subject`, its `source` (`engine` or `host`) and `retry`. The name is the configuration key or fixed ceiling the refusal names (`maxSubjectBytes`, `maxTotalBinaryBytes`, `maxTriangles`, `descriptorBytes`, `workUnitLimit` and the rest) or, for an analysis limit, the evidence the engine names, such as `continuousEvidenceBytes`.
  - `retry` is the `workUnitLimit` value that can still decide the claim, `{ parameter: 'workUnitLimit', value }` for a work budget below the host maximum, set where that claim's budget is set (`test_model` for the run, or its `loadModel` or `expectGeo` option); it is `null` when no argument raises the limit. `@taucad/mcp` advertises and validates `limit` in its `test_model` output schema.
  - The compact `test_model` result of a large run keeps each row's `category` and `limit`.
  - Of the limit rows, only `work-budget` rows name `workUnitLimit`. An admission or analysis limit row says the claim is not decided and that no `test_model` argument raises the limit, and a timeout row no longer points at resource limits. A whole-model claim on a region load, and a region load on a kernel that cannot crop, no longer suggest provisioning more resources or raising `workUnitLimit`.
  - `geospec`: a load the engine or the host refuses to admit (`limit-exceeded`), in a test or in a `describe` body, leaves that test or suite `inconclusive`, with a `GEOSPEC_RESOURCE_LIMIT` diagnostic carrying the limit and what the load needed, instead of a `failed` test with `TEST_FAILED`. Run accounting counts such a test as inconclusive, not failed, unless one of its claims was decided false or could not run. A `limit-exceeded` thrown while a claim runs on a load already admitted (the engine or host out of room for the claim) names no limit of the model, so its test still fails, as an infrastructure failure whose row does not call the claim undecided.
  - `geospec`: the native model loader's own byte refusals carry the engine's capacity shape and name the limit they enforce (`maxTotalBinaryBytes`, or `descriptorBytes` for the 16 MiB descriptor ceiling), with `source: 'host'`.
  - `@taucad/geospec-engine` and `@taucad/cli`: the `geospec` and `tau test` totals name the inconclusive tests, such as `0 passed, 0 failed, 4 selected, 4 inconclusive`.

- `tau mcp`'s CAD tool results name the project root their paths resolved against, and a GeoSpec load can name the folder its paths resolve in. ([#103](https://github.com/taucad/geospec/pull/103))

  - Successful `evaluate_model`, `test_model`, `screenshot` and `export_model` results from `@taucad/host`'s tool registry carry `projectRoot`, the absolute root of the call: `--project`, the folder Codex names with the call, `CLAUDE_PROJECT_DIR`, or the working directory. `@taucad/mcp` keeps it in each structured result and, for inline screenshots, as a `projectRoot:` text line; the host's MCP endpoint keeps it on filed screenshots and shortened GeoSpec reports.
  - `tau mcp` names its start root and where it came from on stderr, and each folder a call names the first time it is used. `tau mcp`, `tau test`, `tau check`, `tau export` and `tau open` share one project-root resolution.
  - `loadModel({ file })` and `loadModel({ source })` take `rootDir`, a canonical project-relative folder the load's paths resolve in, recorded as `rootDir` in the load evidence. Inline-code loads do not take it, in their type and at run time, and a malformed folder is refused as `GEOSPEC_MODEL_OPTION_INVALID`.
  - A `loadModel({ file })` of a file the root does not hold now refuses with `GEOSPEC_MODEL_SOURCE_NOT_FOUND`, a `model-load` failure that names the root and the path it looked for and says that a path from the project root or `rootDir` fixes it, instead of the runtime's untyped `ENOENT`. A failed direct-source read names the root and the joined path too.

- Remove the TypeScript/WASM GeoSpec engine. The compiled engine (`geospec-engine`, published from taucad/geospec) is now the only executor; hosts run specs through `createNativeGeoSpecRunner` from `geospec/runner/native`, the `geospec` CLI, or `createGeoSpecNativeNodePoolRunner` from `@taucad/geospec-engine/native-pool/node`. ([#103](https://github.com/taucad/geospec/pull/103))

  Breaking:

  - `geospec` drops the `./brep`, `./inspection`, `./proofs`, `./runner/node`, `./runner/web`, `./selector` and `./step` subpaths, and with them `analyzeBrep`, `inspectGeometry`, `loadStep`, `createStepLoader`, `createGeoSpecNodeRunner`, `createGeoSpecNodePoolRunner`, `createNodeVmFileSystem` (use `@taucad/geospec-engine/node-filesystem`), `createGeoSpecWebRunner` and `createGeoSpecWebPoolRunner`. Authored specs that import those subpaths now fail when the spec is bundled; inside the VM only `geospec` and `geospec/model` remain.
  - `geospec` drops root `createGeoSpec` and the `GeoSpec`, `AnalyzeMeshOptions`, `AnalyzeMeshResult`, `LoadMeshOptions` and `LoadMeshResult` types; `geospec/mesh` drops `loadMesh`, `analyzeMesh` and `analyzeMeshOverlap` (use `evaluateGeoSpecNativeQuery` from `geospec/assertion-client`); `geospec/runner` drops `chargeBudget` and `checkBudget`.
  - `geospec/engine` keeps only the matcher registry (`geoSpecMatcherDescriptors`, `normalizeGeoSpecExpected`) and the canonical-JSON helpers. The engine registry (`registerGeoSpecEngine`, `getGeoSpecEngine*`, `describeGeoSpecEngine`, `GeoSpecEngineImplementation`, `GeoSpecEngineHostBindings`, `GeoSpecEngineUnavailableError` and the `GEOSPEC_ENGINE_UNAVAILABLE` code), `geoSpecEngineProtocolVersion`, `geoSpecMatcherRegistryVersion` and every protocol-2 request, result and event type are removed.
  - `geospec/runner/worker` drops `startGeoSpecPoolWorkerHost` and `GeoSpecPoolWorkerHostOptions`, and the pool `initialize` message no longer carries `compiledWasmModule`. `GeoSpecRunnerOptions` and `RunGeoSpecModuleOptions` lose `modelLoader`, `stepLoader` and `internalProfile` and require `nativeAssertions`; `createCollector` requires `nativeAssertions` and `GeoSpecNativeCollector` merges into `GeoSpecCollector`; `createModelLoader` requires `engine`; `loadModel` called outside a runner throws `GEOSPEC_MODEL_LOADER_UNAVAILABLE`.
  - `@taucad/geospec-engine` drops its root export and the `./register`, `./register/node`, `./native/opencascade/single`, `./native/opencascade/single/wasm` and `./native/opencascade/single/wasm-url` subpaths, the bundled OCCT WebAssembly build and its LGPL notices. It now publishes the `geospec` bin, `./node-filesystem`, `./native-pool/node` and `./package.json`.
  - The `geospec` CLI no longer accepts `--cache-directory` or `--no-cache`; the compiled engine keeps no persistent evidence cache. `GeoSpecCliHost` loses `flush`, and `createRunner` no longer receives `cache` or `cacheDirectory`.

- The generated agent skills show each signature in full and say where the rest is. A union type alias with object variants lists every variant on its own line, so `cad-picovoxel` shows all five `CreateVoxelsOptions` shapes instead of the first. A small type that several shown signatures name is declared once: `geospec-authoring` declares `GeoSpecNumericExpectation` once instead of five times. ([#103](https://github.com/taucad/geospec/pull/103))

  The marker under a trimmed class names the members it hides (`cad-manifold`'s `Manifold` marker lists `levelSet`, `hull`, `slice` and the rest), and `api-index.md` gives each top-level symbol the line range of the file that holds it, which the reference map tells the agent to read instead of grepping the skill directory. `cad-replicad` declares Tau's `ShapeConfig`, with `density` and `interfaces`, and no longer the upstream one beside it.

  `geospec-authoring` gains a Ceilings table: the 64 MiB subject and resource limits with the 72-bytes-per-triangle mesh export that puts admission near 930,000 triangles, the 128 MiB total, the decoded triangle and vertex counts, the 32 MiB continuous-evidence limit of `toHaveNoComponentInterference`, and the `workUnitLimit` cap, plus when to load `format: 'step'`. Its limit advice now says only a `work-budget` row's `limit.retry` is a retry and every other limit is reported as not decided.

  `cad-picovoxel` states the same triangle ceiling beside `voxelSize` and coarsens on `PICO_OUT_OF_MEMORY` only while the thinnest wall still spans about three voxels. A `geospec-engine` test compares the table's admission limits with the ones the installed engine reports.

- `geospec check <file.step|file.stp|file.glb>` runs one bundled validity spec on a model file with no `*.geospec.ts`: no error diagnostics, closed edge incidence and a bounding box with positive size, plus mesh integrity for a GLB or a valid BRep with closed shells for a STEP file, each claim its own test. `--components <n>` adds an exact connected-component count, and `--json` prints the same report as `geospec run`. The spec is served from memory in the file's folder, so nothing is written there; `createGeoSpecNodePoolRunner` takes the in-memory `sources` that make this work. ([#103](https://github.com/taucad/geospec/pull/103))

  The legacy evidence and STEP structure types are gone from the public surface. The root barrel keeps `GeometryDiagnostic` and `Vec3` (also as `GeoSpecVec3`), which the matcher types name, and `geospec/mesh` keeps `GeometryDiagnostic`, `GeometryExportIntent`, `GeometryFileFormat`, `MeshFileFormat`, `Vec3`, `GeoSpecUnit`, `MeshSource` and `MeshBufferSource`. `BrepEvidence`, `StepEvidence`, `MeshEvidence`, `GeometrySubject`, `GeometryStats`, `MeshQualityStats`, `CheckResult`, the watertight, bounding-box and component failure records and the `Xde*` STEP structure types described the removed TypeScript engine; no published API returned them. The agent bundles are regenerated.

### 🩹 Fixes

- GeoSpec's model loaders, Tau project artifact export and `tau export` open their one-shot runtime documents with `watch: false`. A one-shot export subscribes no native file watcher, so its teardown has no watcher to race and cannot abort a Node worker pool on macOS with a fatal `napi_throw` from `@parcel/watcher`. ([#103](https://github.com/taucad/geospec/pull/103))
- The Node pool keeps a worker's initialization error code, so a caller of `run()` can tell a missing `geospec-engine` (`ERR_MODULE_NOT_FOUND`) from any other startup failure. The exit that follows an initialization error no longer replaces its reason. ([#103](https://github.com/taucad/geospec/pull/103))
