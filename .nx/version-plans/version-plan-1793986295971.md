`geospec run --watch` runs once, then again whenever a file under the project changes its bytes, on the same worker processes. Each worker keeps the models it loaded and the facts measured on them, and each file goes back to the worker that ran it before, so a rerun after a spec edit parses no model and a model edit parses that one model again. A retained model is keyed by the digest of its bytes: changed bytes are always admitted afresh, and reports equal a fresh run's apart from `durationMs`, the per-run nonce in each `loadId` and `bundleSha256`. A config change ends the watch with exit code 1.

`createGeoSpecNodePoolRunner` gains `retention` (`defaultGeoSpecSubjectRetention`: 24 models per worker, none kept while the worker's resident memory is over 2 GiB), off by default. A pool that is run again replaces a worker that died since the last run. `setupGeoSpecVitestProject` gains `persistentEngine`, which shares one engine and its retained models across the files one Vitest worker process runs; off by default.
