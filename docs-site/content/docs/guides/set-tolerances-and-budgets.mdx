---
title: Set tolerances and budgets
description: State how close a measurement must come, compare with strict bounds, and give each claim the work it needs.
---

Every claim carries two limits: a `tolerance` in its payload that says how close the measurement must come to the expected value, and a `workUnitBudget` that says how much work the engine may spend deciding it. Both are part of the claim, so both are part of the result.

## Run out of budget

The gear is a mesh of 624 triangles, and a bounding box over a mesh charges work units per triangle. The claim below is refused before it measures anything.

<SpecDemo subject="gear">

```ts
expectGeo(part, { workUnitLimit: 100 }).toHaveBoundingBox({ size: { z: 5 } });
```

</SpecDemo>

The refusal is `MATCHER_TIMEOUT`, with `budget: 100` and `unitsUsed: 3744` in its details. Set `workUnitBudget` to 10000 and the claim passes. Then add `tolerance: 0` beside `size` and it fails: the triangles span 4.999976634979248 mm, not 5.

## Tolerance

A value is equal when `abs(measured - expected) <= tolerance`. The default is 0.02 mm, and `tolerance: 0` demands the nominal value, which a STEP box meets and a tessellated mesh rarely does. The tolerance applies to every value in the payload, each axis of a point or a bounding box, the offset of a plane, the radius of a cylinder or a mass. The result records it under `normalizedExpected`, so two readers of the same result see the same rule.

A negative tolerance is an `invalid-claim` error, `tolerance must be nonnegative.`, and so is a bounding-box payload with a tolerance and no bound: a tolerance alone constrains nothing.

## Strict comparisons

Where a payload takes a numeric expectation, write a number or an object with any of `value`, `greaterThan`, `greaterThanOrEqual`, `lessThan` and `lessThanOrEqual`. Tolerance applies to `value` only; the four comparisons are strict as written.

```ts
payload: { kind: 'volume', expected: { value: { greaterThan: 30000, lessThan: 31000 } } }
```

This passes on the plate, which measures 30429.20367 mm³. `{ greaterThan: 30429.21 }` fails, because no tolerance widens a comparison, and the failure message states the rule: `Volume is 30429.20367320504 (brep evidence), which does not satisfy > 30429.21 within 0.02.` An object with none of the five fields is an `invalid-claim` error.

## Work-unit budgets

`workUnitBudget` is a required field of every claim, a positive integer; a claim without one is an `invalid-claim` error. The engine's configuration, reported by `initialize` as `defaultWorkUnitBudget`, is 8,000,000, which the Python package writes into each claim unless `GeoSpecEngine` is given a `work_unit_budget`. The engine charges work before it computes or reads a cache, so the count is the same on every host and every run, and it never depends on wall time. A claim that exceeds its budget is refused with `MATCHER_TIMEOUT`: the diagnostic names the matcher, the budget and the units used, and the claim was not decided.

```json
{ "budget": 100, "matcher": "toHaveBoundingBox", "unit": "work-units", "unitsUsed": 3744 }
```

A refusal for budget is never a pass and never a failure. Raise the budget for that claim, or narrow the claim; a budget of 0 is rejected as `invalid-claim`.

## Never widen a tolerance to pass

A failed claim reports what it measured. Read the measurement, then fix the model or correct the expectation to the value the design states. Widening `tolerance` until the claim passes records a looser requirement than the design has, and the next part that drifts inside the wider band passes too. The engine's own failure messages end with `preserve the authored tolerance.` for the same reason. A refusal is treated the same way: never rewrite a claim so that a refusal counts as a pass; [Read a refusal](/docs/guides/read-a-refusal) covers what to change instead.

## Variations

**A tolerance per claim.** Tolerance lives in the payload, so two claims on one subject can carry different ones: `0.02` on a machined bore and `0.5` on a cast surface area.

**A tolerance with its own name.** `toHaveConnectedComponents` takes `toleranceMm`, the gap below which two pieces count as one. It defaults to `tolerance`, then to 0.02 mm. [Check meshes](/docs/guides/check-meshes) covers it.

**Mesh claims cost more.** Bounds, closure, volume and integrity on the gear each charge 3,744 units; a component count charges 49,005 and an `inspectGeometry` selector 52,138. A twelve-triangle box passes under 100, and a STEP hole claim charges 3.

**Budgets on queries.** A query charges the same way. `analyzeMeshOverlap` refuses with `MATCHER_TIMEOUT` naming the pair whose Boolean it could not finish; [Query geometry](/docs/guides/query-geometry) covers the queries. The [matcher reference](/docs/reference/overview#shared-payload-rules) states the shared rules every payload follows.
