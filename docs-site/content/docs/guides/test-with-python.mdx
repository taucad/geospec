Turn a part into a pytest suite: load the exported STEP or GLB, state what it must be, and read the outcome from the run. The wheel registers a pytest plugin, so a test file needs no fixtures of its own.

```bash tab="pip"
pip install geospec-engine
```

### 1. Write the test

`load_model` reads a file under the pytest rootpath. `expect_geo` returns a report on a pass and raises `GeoSpecAssertionError` on a failed or refused claim, so a passing test returns.

```python title="tests/test_part.py"
from geospec import expect_geo, load_model


def test_plate_size():
    plate = load_model(file="models/plate-with-through-bore.step", format="step")
    expect_geo(plate).to_have_bounding_box(size={"x": 40, "y": 40, "z": 20})


def test_plate_bore():
    plate = load_model(file="models/plate-with-through-bore.step", format="step")
    expect_geo(plate).to_have_circular_hole(diameter=12)


def test_gear_bore():
    gear = load_model(file="models/involute-gear.glb", source_unit="mm")
    expect_geo(gear).to_have_circular_hole(diameter=4)
```

`format` defaults to `glb`, and `source_unit` to `auto` for STEP and `m` otherwise, so a millimetre GLB declares `source_unit="mm"`. Each matcher takes keyword fields or one positional dict, never both.

A failure names what was measured; a refusal names the evidence the subject lacks. Fix the model for the first and the subject for the second: admit the gear's STEP export, or claim what a mesh can answer.

### 2. Read the code, not the message

The error carries the whole result: `code` is the first diagnostic code and `result["status"]` tells a failure from a refusal, so a test can state that a claim refuses on a mesh:

```python title="tests/test_refusal.py"
import pytest
from geospec import GeoSpecAssertionError, expect_geo, load_model


def test_gear_bore_refuses():
    gear = load_model(file="models/involute-gear.glb", source_unit="mm")
    with pytest.raises(GeoSpecAssertionError) as raised:
        expect_geo(gear).to_have_circular_hole(diameter=4)
    assert raised.value.result["status"] == "refused"
    assert raised.value.code == "GEOSPEC_EVIDENCE_UNSUPPORTED"
```

The failed plate bore raises `GEOSPEC_FEATURE_MISMATCH` with `status == "failed"`. Every diagnostic is under `raised.value.diagnostics`, with `code`, `message` and `suggestion`.

### 3. Point the plugin at a model folder

The plugin creates one `GeoSpecEngine` per test, lazily, with `model_root` at the rootpath. Override `geospec_engine_factory` in `conftest.py` to root paths elsewhere or set a budget:

```python title="conftest.py"
from pathlib import Path

import pytest
from geospec import GeoSpecEngine


@pytest.fixture
def geospec_engine_factory(pytestconfig: pytest.Config):
    models = Path(pytestconfig.rootpath) / "models"
    return lambda: GeoSpecEngine(model_root=str(models), work_unit_budget=2_000_000)
```

Tests then load `file="plate-with-through-bore.step"`. A path that leaves `model_root` raises `GEOSPEC_MODEL_PATH_OUTSIDE_ROOT` before any engine runs.

### 4. Check without raising

`evaluate_geo` returns the report whatever the outcome; `report.passed` is `False` for a refusal as for a failure. `query_geo` runs one of the five queries and returns its evidence:

```python title="tests/test_report.py"
from geospec import evaluate_geo, load_model, query_geo


def test_gear_bounds_without_raising():
    gear = load_model(file="involute-gear.glb", source_unit="mm")
    report = evaluate_geo(gear, "toHaveBoundingBox", {"size": {"z": 5}})
    assert report.result["status"] == "passed"


def test_plate_brep_query():
    plate = load_model(file="plate-with-through-bore.step", format="step")
    report = query_geo(plate, "analyzeBrep")
    assert report.result["evidence"]["brep"]["boundingBox"]["size"] == [40, 40, 20]
```

### 5. Run it in CI

CPython 3.13 and 3.14 wheels ship for manylinux_2_28 x86_64 and macOS arm64, which `ubuntu-latest` and `macos-latest` are:

```yaml title=".github/workflows/geospec.yml"
on: [push, pull_request]
jobs:
  geospec:
    strategy:
      matrix:
        os: [ubuntu-latest, macos-latest]
        python: ['3.13', '3.14']
    runs-on: ${{ matrix.os }}
    steps:
      - uses: actions/checkout@v5
      - uses: actions/setup-python@v6
        with:
          python-version: ${{ matrix.python }}
      - run: pip install geospec-engine pytest
      - run: pytest -q --tb=short
```

## Variations

**Outside pytest.** `GeoSpecEngine` is a context manager and `load_model` needs an active one: `with GeoSpecEngine(model_root="."):` then `load_model(file="part.step", format="step")`, as the [quick start](/docs) shows. Give each thread its own engine.

**Negation.** `expect_geo(part).not_.to_have_bounding_box(size={"x": 12})` passes when the claim does not hold and raises `GEOSPEC_NEGATED_MATCH` when it does. A refusal stays a refusal under `.not_`.

**Regular expressions.** Selectors take `GeoSpecRegex(pattern, flags)`, never an `re.Pattern`; [Compare parts](/docs/guides/compare-parts) uses them.

**Named claims.** Pass `claim_id="size"` to `expect_geo` when you store `canonical_result_bytes`: an auto-generated id enters the bytes. [Reproduce a result](/docs/guides/reproduce-a-result) hashes them.

**`minimumDistance`.** `query_geo` raises `ValueError` for it; the [matcher reference](/docs/reference/queries#minimumdistance) shows the request to send through `geospec_engine_native.Engine` instead.
