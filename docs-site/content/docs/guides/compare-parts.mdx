---
title: Compare parts
description: Select two parts of an assembly by name, claim their clearance or non-interference, and query the exact distance between them.
---

Claim how two parts of an assembly sit against each other. The parts are the occurrences of a STEP file or the named nodes of a GLB, and the engine answers each pair exactly or refuses it. A selector is an exact occurrence name or a regular expression, and must resolve to one entity. The bundled demo models are single parts, so the examples run on fixtures from the engine's repository, each copied next to the spec.

### 1. Name the parts and claim a clearance

`packages/geospec-engine/native/occt/rust/tests/fixtures/box-clearance/two-mm.step` holds two 10 mm cubes named `subject` and `target`, 2 mm apart along x.

<TypeScript>

```ts title="clearance.geospec.ts"
import { expectGeo, it } from 'geospec';
import { loadModel } from 'geospec/model';

const boxes = () => loadModel({ source: 'two-mm.step', format: 'step' });
const clearance = (subject: string | RegExp, target: string, min = 2) => ({
  relationships: [{ kind: 'clearance' as const, subject, target, min }],
});

it('clears by 2 mm', async () => expectGeo(await boxes()).toHaveSpatialRelationships(clearance('subject', 'target')));
it('clears by 3 mm', async () => expectGeo(await boxes()).toHaveSpatialRelationships(clearance('subject', 'target', 3)));
it('matches a pattern', async () => expectGeo(await boxes()).toHaveSpatialRelationships(clearance(/^sub/, 'target')));
it('matches both boxes', async () => expectGeo(await boxes()).toHaveSpatialRelationships(clearance(/t/, 'target')));
it('names a missing part', async () => expectGeo(await boxes()).toHaveSpatialRelationships(clearance('subject', 'nut')));
```

One `it` per claim keeps every verdict visible, because a failed or refused chain throws. `npx geospec run --file clearance.geospec.ts`, the runner from `@taucad/geospec-engine`, prints the tests that did not pass, with code and message, and counts a refused test as neither passed nor failed:

<Python>

```python title="clearance.py"
from geospec import GeoSpecEngine, GeoSpecRegex, evaluate_geo, load_model

with GeoSpecEngine(model_root="."):
    boxes = load_model(file="two-mm.step", format="step")

    def clearance(subject, target, minimum=2):
        relationship = {"kind": "clearance", "subject": subject, "target": target, "min": minimum}
        report = evaluate_geo(boxes, "toHaveSpatialRelationships", {"relationships": [relationship]})
        print(report.result["status"], *(diagnostic["code"] for diagnostic in report.diagnostics))

    clearance("subject", "target")
    clearance("subject", "target", minimum=3)
    clearance(GeoSpecRegex("^sub"), "target")
    clearance(GeoSpecRegex("t"), "target")
    clearance("subject", "nut")
```

A pattern is a `GeoSpecRegex`, never an `re.Pattern`. `evaluate_geo` returns the report whatever the outcome, where `expect_geo` would raise at the first failed or refused claim; [Test with Python](/docs/guides/test-with-python) covers both.

### 2. Read a clearance

The first claim passes with `[{ "distance": 2 }]` as its measured evidence. The second asks for 3 mm and fails with `GEOSPEC_SPATIAL_RELATIONSHIP_MISMATCH`; its witnesses hold the closest points, (10, 0, 0) and (12, 0, 0), as exact rationals. `^sub` matches one occurrence and passes; `t` matches both cubes, so the claim is refused with `GEOSPEC_SELECTOR_AMBIGUOUS`; `nut` names no occurrence, and the claim is refused with `GEOSPEC_SELECTOR_UNSUPPORTED_EVIDENCE`, because the file carries no authored interface names to resolve it against.

### 3. Claim no interference

On STEP, `toHaveNoComponentInterference` refuses with `GEOSPEC_EVIDENCE_UNSUPPORTED` unless a pair carries an allowance; the [relationships reference](/docs/reference/relationships) states the rule. On a GLB it computes each pair's shared volume exactly, with components labelled `node#primitive`. `packages/geospec-engine/bench/fixtures/performance-lab/generated/assembly.glb` holds nodes `cubeA` and `cubeB`, 20 mm apart, and loads with `sourceUnit: 'mm'`:

- `toHaveNoComponentInterference()` passes; the pair reads `intersectionNumerator: "0"` and `withinAllowance: true` under the measured evidence.
- `toHaveNoComponentInterference({ pairs: [{ left: 'cubeA#0', right: 'pin#0' }] })` is refused with `GEOSPEC_SELECTOR_UNMATCHED`: no component is named `pin#0`.
- A clearance of `min: 20` between `{ kind: 'body', of: 'cubeA#0' }` and `{ kind: 'body', of: 'cubeB#0' }` passes with `distanceSquaredNumerator: "400"`, 20 mm as an exact square. A plain `'cubeA'` resolves STEP occurrences only, so a mesh endpoint is a body selector.

### 4. Query the distance

<TypeScript>

`minimumDistance` reports the exact distance between two occurrences of an AP242 STEP assembly, with a closest point on each. It runs on the assertion client, as [Query geometry](/docs/guides/query-geometry) describes, with `payload: { pair: [{ occurrencePath: 'subject' }, { occurrencePath: 'target' }] }`, and its result is typed rather than a report: `complete` with a `fact`, `refused` with a `code` and `message`, or `interrupted`. On the two cubes the fact reads `distance: 2`, `points: [[10, 0, 0], [12, 0, 0]]` and `assurance: 'exact-brep'`; a mesh is refused with `unsupported-evidence`.

</TypeScript>

<Python>

`minimumDistance`, the exact distance between two occurrences of an AP242 STEP assembly, is a TypeScript-only query: `query_geo` raises `ValueError` for it. Claim the distance as a clearance instead, as step 1 does.

## Variations

**Contact and alignment.** `contact` asks two parts to touch within `tolerance`; the 2 mm gap fails it. `parallel`, `perpendicular`, `coaxial` and the other alignment kinds need a face, axis or plane selector on each side, such as `{ kind: 'face', of: 'subject', query: { surfaceType: 'plane', normal: { direction: [1, 0, 0] } } }`; a whole occurrence is refused with `GEOSPEC_SELECTOR_UNSUPPORTED_EVIDENCE`.

**Pairs you mean to touch.** An `allowances` entry with `left`, `right`, `reason` and `kind: 'intentionalInterference'` waives a pair; with one for `subject` and `target`, the STEP claim of step 3 passes. [Read a refusal](/docs/guides/read-a-refusal) says what each code asks for.

**Limits the file carries.** `toSatisfyParallelPlaneDistance()` takes no argument: the STEP file declares the two faces and the band between them. The two-cube file declares nothing, so the claim is refused with `GEOSPEC_CERTIFICATE_UNVERIFIED`; the [contracts reference](/docs/reference/contracts#tosatisfyparallelplanedistance) describes the declaration.
