`npm install geospec@beta geospec-engine` gives TypeScript the assertions and the engine; `pip install geospec-engine` gives Python the `geospec` package with the engine inside. [Install](/docs/install) covers the engine artifact each host loads.

The examples run beside the demo models [`plate-with-through-bore.step`](/demo/plate-with-through-bore.step), a 40 × 40 × 20 mm STEP plate with a 10 mm bore, and [`involute-gear.glb`](/demo/involute-gear.glb), a gear mesh in millimetres.

## Every option and its default

<TypeScript>

```ts
import { readFile } from 'node:fs/promises';
import { expectGeo } from 'geospec';
import { createModelLoader } from 'geospec/model';
import { Engine } from 'geospec-engine/node';

const loadModel = createModelLoader({
  engine: new Engine(), // required
  readSource: async (path) => new Uint8Array(await readFile(path)), // required for a path
  format: 'glb', // default for every load
});
const plate = await loadModel({
  source: 'plate-with-through-bore.step', // a path, or the bytes
  format: 'step', // default 'glb'; also 'stp'
  workUnitLimit: 8_000_000, // default: the engine's 8,000,000
});
const gear = await loadModel({ source: 'involute-gear.glb', sourceUnit: 'mm' }); // default 'm' for a mesh file
const size = expectGeo(plate, { workUnitLimit: 8_000_000 }) // default: the subject's, then the engine's
  .toHaveBoundingBox({ size: { x: 40, y: 40, z: 20 }, tolerance: 0.02 }); // default tolerance 0.02 mm
console.log(size.report.claimId, size.report.status, size.report.claim.workUnitBudget); // geospec-claim-1 passed 8000000
await loadModel.dispose();
```

</TypeScript>

<Python>

```python
from geospec import GeoSpecEngine, expect_geo, load_model

engine = GeoSpecEngine(
    model_root=".",          # default None: file= refuses until set
    work_unit_budget=None,   # default: the engine's 8_000_000
    execution_permits=None,  # up to the host's CPU count
    cache_root=None,         # with project_root: filesystem cache
    project_root=None,
    model_loader=None,       # required for load_model(code=...)
)
with engine:
    plate = load_model(
        file="plate-with-through-bore.step",  # under model_root; or source=bytes | path
        format="step",        # default "glb"; also "gltf" and "stp"
        source_unit="auto",   # default "auto" for STEP, "m" otherwise
        resources=(),         # glTF buffers: [{"name": ..., "source": ...}]
        ingest_options=None,  # STEP {"name": ...}; changes the hash
        name="plate.step",    # provenance name; default: file
    )
    report = expect_geo(plate, claim_id="size").to_have_bounding_box(size={"x": 40, "y": 40, "z": 20})
    print(report.passed, report.result["status"], report.claim["workUnitBudget"])  # True passed 8000000
```

</Python>

## Entry points

<TypeScript>

- `geospec`: `expectGeo`, `geoSpecMatcherNames` and the types; `describe`, `it` and `test` for spec files.
- `geospec/model`: `loadModel`, `createModelLoader`, `GeoSpecModelLoadError`.
- `geospec/assertion-client`: `createGeoSpecAssertionClient`, `GeoSpecAssertionError`, `geoSpecMaximumWorkUnitLimit`.
- `geospec/runner/native`: `createGeoSpecNativeModelLoader`.
- `geospec/vitest`: `setupGeoSpecVitest`, `installGeoSpecVitest`, `createGeoSpecVitestAdapter`.
- `geospec-engine`: `Engine`, `initialize`, `canonicalize`, `ProtocolError` (WASM).
- `geospec-engine/node`: `Engine`, `canonicalize`, `ProtocolError` (native addon).
- `@taucad/geospec-engine`: the `geospec` command; a spec never imports it.

</TypeScript>

<Python>

`geospec` exports 52 names: the nine documented here, `GeoSpecMatchers`, `GeoSpecLoadModelOptions` and the typed dicts behind them; `geospec_engine_native` is the engine over `bytes`, and the wheel registers the pytest plugin `geospec`.

</Python>

The engine's byte protocol is for embedders and lives in the [engine package README](https://github.com/taucad/geospec/blob/main/packages/geospec-engine/README.md).

## Load a model

### loadModel

Read a model, admit it to the engine and return the subject claims measure.

<TypeScript>

```ts
loadModel(options: LoadModelSourceOptions): Promise<GeoSpecSubject>
```

- **Parameters:** as annotated in the options block, plus `resources`, named glTF buffers, and `name`, `path` and `parameters` for the load record.
- **Returns:** an opaque `GeoSpecSubject`, alive until `loadModel.dispose()`.
- **Throws:** `GeoSpecModelLoadError`; its first diagnostic's `code` names the cause: `GEOSPEC_NATIVE_MODEL_FORMAT_UNSUPPORTED` outside `glb`, `step` and `stp`, `GEOSPEC_MODEL_OPTION_UNSUPPORTED` for `mesh`, `stepStreaming`, the mesh tolerances and `sourceUnit` on STEP, `GEOSPEC_NATIVE_RUNTIME_UNAVAILABLE` for `{ file }` without a CAD runtime.

```ts
const plate = await loadModel({ source: 'plate-with-through-bore.step', format: 'step' });
const gear = await loadModel({ source: 'involute-gear.glb', sourceUnit: 'mm' });
const size = expectGeo(plate).toHaveBoundingBox({ size: { x: 40, y: 40, z: 20 } });
console.log(
  size.report.status,
  size.report.evidence.measured.size,
  size.report.evidence.subjectContentHash.slice(0, 16),
);
// passed [ 40, 40, 20 ] fb622c854152ce81
```

</TypeScript>

<Python>

```python
load_model(*, file=..., source=..., format="glb", source_unit=..., resources=(), ingest_options=None, name=...) -> GeoSpecSubject
```

- **Parameters:** as annotated in the options block: exactly one of `file` and `source`; `format`; `source_unit`; `resources`, each with exactly `name` and `source`; `ingest_options`; `name`.
- **Returns:** a frozen `GeoSpecSubject` (`engine`, `slot`, `identity_field`, `identity`, `provenance`), alive until `close()` on it or on the engine.
- **Raises:** `GeoSpecAssertionError` with `GEOSPEC_MODEL_HOST_UNAVAILABLE`, `GEOSPEC_MODEL_PATH_OUTSIDE_ROOT`, `GEOSPEC_MODEL_FORMAT_UNSUPPORTED`, `GEOSPEC_MODEL_OPTION_UNSUPPORTED` or `invalid-field`; `FileNotFoundError` for a missing file; `TypeError` for `file` with `source`.

```python
plate = load_model(file="plate-with-through-bore.step", format="step")
gear = load_model(file="involute-gear.glb", source_unit="mm")
print(plate.provenance["primary"]["sha256"][:16], plate.identity_field, gear.identity[:16])  # fb622c854152ce81 subjectHash a9913a341848cb6b
```

</Python>

### createModelLoader

<TypeScript>

```ts
createModelLoader(defaults: CreateModelLoaderOptions): ManagedGeoSpecModelLoader
```

- **Parameters:** `engine`; `readSource`, required for a path source; `format` and the mesh options as defaults; `projectPath`, `runtime` and `sourceAdapters` for code models.
- **Returns:** `loadModel` with `dispose()`, which releases every subject it admitted.
- **Throws:** nothing on creation; a path load without `readSource` throws `GEOSPEC_NATIVE_SOURCE_READER_UNAVAILABLE`.

```ts
const plate = await loadModel({ source: 'plate-with-through-bore.step', format: 'step' });
await loadModel.dispose();
expectGeo(plate).toHaveVolume({ value: 30429.2 }); // TypeError GEOSPEC_SUBJECT_INVALID: reload it within its live scope
```

</TypeScript>

<Python>

`GeoSpecEngine` is the loader: it owns its subjects and runs on the thread that created it.

```python
GeoSpecEngine(*, model_root=None, work_unit_budget=None, execution_permits=None, cache_root=None, project_root=None, model_loader=None)
```

- **Parameters:** as in the options block above; `cache_root` and `project_root` go together.
- **Returns:** the engine; as a context manager it is `load_model`'s engine and closes on exit, releasing every subject.
- **Raises:** `ValueError` for a budget that is not a positive safe integer, permits outside 1 to the CPU count, or a cache root alone; `RuntimeError` off the owner thread or after `close()`.

```python
with GeoSpecEngine(model_root=".") as engine:
    print(engine.protocol_version, engine.registry_version, len(engine.capabilities), engine.configuration["defaultWorkUnitBudget"])  # 3 5 32 8000000
```

</Python>

## State a claim

### expectGeo

Start a chain on a subject; each matcher call is one claim, answered in that call. The [matcher reference](/docs/reference/overview) lists the 26 matchers and their fields; a scalar matcher takes `{ value, tolerance }`.

<TypeScript>

```ts
expectGeo(subject: GeoSpecSubject, options?: GeoSpecExpectOptions): GeoSpecMatcher
```

- **Parameters:** the subject; `workUnitLimit`, this chain's budget.
- **Returns:** the matchers and `.not`, each returning a `GeoSpecAssertion` with the engine's `report`; claim ids count `geospec-claim-N` per process, shared with the assertion client.
- **Throws:** `GeoSpecAssertionError` for a failed or refused claim, carrying the same report; `ProtocolError` `invalid-claim` for a payload the engine rejects; `TypeError` for a subject outside its live scope or a `workUnitLimit` outside 1 to the host's maximum.

```ts
const noHole = expectGeo(plate).not.toHaveCircularHole({ diameter: 12 });
console.log(noHole.report.claimId, noHole.report.polarity, noHole.report.status); // geospec-claim-1 negative passed
expectGeo(gear, { workUnitLimit: 100 }).toHaveBoundingBox({ size: { z: 5 } }); // GeoSpecAssertionError: refused, MATCHER_TIMEOUT, details.used 3744
```

</TypeScript>

<Python>

```python
expect_geo(subject, *, claim_id=None) -> GeoSpecMatchers
```

- **Parameters:** the subject; `claim_id`, default `geospec-claim-N` from one counter per engine.
- **Returns:** the matchers and `.not_`, each returning a `GeoSpecAssertionReport`; a matcher is the snake_case registry name and takes keyword fields with their camelCase names (`toleranceMm=`), or one positional dict.
- **Raises:** `GeoSpecAssertionError` for a failed or refused claim, and with code `invalid-claim` for a payload the engine rejects; `AttributeError` for a name outside the registry; `TypeError` for a positional dict with keyword fields.

```python
report = expect_geo(plate).to_have_bounding_box(size={"x": 40, "y": 40, "z": 20})
print(report.claim["claimId"], report.result["status"], report.result["evidence"]["measured"]["size"])  # geospec-claim-1 passed [40, 40, 20]
try:
    expect_geo(plate).to_have_circular_hole(diameter=12)
except GeoSpecAssertionError as error:
    print(error.code, error.result["status"], error)  # GEOSPEC_FEATURE_MISMATCH failed No circular hole matches diameter 12 within 0.02 mm.
expect_geo(gear).not_.to_have_circular_hole(diameter=4)  # GeoSpecAssertionError: refused, GEOSPEC_EVIDENCE_UNSUPPORTED, under either polarity
```

`evaluate_geo(subject, capability, *arguments, claim_id=None, polarity="positive")` runs one matcher by registry name and returns the report whatever the status, with `passed` `False` for a refusal; a bad payload raises `geospec_engine_native.ProtocolError`, unwrapped.

</Python>

## Query geometry

The five queries, `analyzeMesh`, `analyzeBrep`, `inspectGeometry`, `analyzeMeshOverlap` and `queryPmi`, report what the engine measured, take positive polarity only, and fail rather than refuse without the evidence they read. [Query geometry](/docs/guides/query-geometry) reads the reports.

### createGeoSpecAssertionClient

<TypeScript>

A client runs chains and queries outside a test runner, on subjects from `createGeoSpecNativeModelLoader({ engine, readSource })` in `geospec/runner/native`: its `loadModel` returns `{ subjectHash, load }`, `releaseAll()` releases them, and the root `expectGeo` rejects them with `TypeError` `GEOSPEC_SUBJECT_INVALID`.

```ts
createGeoSpecAssertionClient(options: GeoSpecAssertionClientOptions): GeoSpecAssertionClient
```

- **Parameters:** `engine`; `workUnitLimit`, every claim's budget unless the chain or the subject sets one; `claimId(matcher, sequence)`; `evidenceProfile`, `complete` or `bounded`; `subjectSlot`; `maximumWorkUnitLimit`.
- **Returns:** `expectGeo(subject, options?)`, whose matchers return the `GeoSpecCanonicalClaimReport` directly, and `query`.
- **Throws:** as `expectGeo`; a subject of another engine, or one released by `releaseAll()`, throws `ProtocolError` `invalid-claim`.

```ts
import { createGeoSpecAssertionClient } from 'geospec/assertion-client';
import { createGeoSpecNativeModelLoader } from 'geospec/runner/native';

const loadModel = createGeoSpecNativeModelLoader({ engine, readSource });
const { expectGeo, query } = createGeoSpecAssertionClient({ engine });
const plate = await loadModel({ source: 'plate-with-through-bore.step', format: 'step' });
const volume = expectGeo(plate).toHaveVolume({ value: 30429.2 });
console.log(plate.subjectHash.slice(0, 16), volume.claimId, volume.status, volume.claim.workUnitBudget); // da21b0d6142fc5fb geospec-claim-1 passed 8000000
```

</TypeScript>

<Python>

Python needs no client: `expect_geo`, `evaluate_geo` and `query_geo` use the engine that owns the subject.

</Python>

### query

<TypeScript>

```ts
client.query(options: GeoSpecQueryOptions): Promise<GeoSpecCanonicalClaimReport>
client.query(options: MinimumDistanceQuery): Promise<MinimumDistanceResult>
```

- **Parameters:** `capability`; `subject`, from the native loader or a bare `{ subjectHash }`; `payload`, omitted for `analyzeMesh` and `analyzeBrep`; `claimId`, which leaves the shared counter alone.
- **Returns:** the report; `minimumDistance` returns `{ status: 'complete', fact }` or `{ status, code, message }` (`unsupported-evidence` without AP242 provenance).
- **Throws:** `ProtocolError` `invalid-claim` for an unknown payload field; `TypeError` for a subject without exactly one of `subjectHash` and `contentHash`.

```ts
const brep = await query({ capability: 'analyzeBrep', subject: plate });
console.log(brep.claimId, brep.status, Object.keys(brep.evidence).join(',')); // geospec-claim-2 passed brep,diagnostics,success
await loadModel.releaseAll();
```

</TypeScript>

<Python>

```python
query_geo(subject, capability, payload=None, *, claim_id=None) -> GeoSpecAssertionReport
```

- **Parameters:** the subject; a query name; `payload`, a mapping whose regular-expression selectors are `GeoSpecRegex(pattern, flags="")`, since a compiled `re.Pattern` raises `TypeError`; `claim_id`.
- **Returns:** the report.
- **Raises:** `ValueError` for `minimumDistance` or any capability that is not a query; `geospec_engine_native.ProtocolError` for an unknown payload field, unwrapped.

```python
brep = query_geo(plate, "analyzeBrep")
print(brep.result["status"], sorted(brep.result["evidence"]))  # passed ['brep', 'diagnostics', 'success']
print(query_geo(gear, "analyzeBrep").diagnostics[0]["code"])  # GEOSPEC_BREP_EVIDENCE_UNAVAILABLE
query_geo(plate, "minimumDistance")  # ValueError: GeoSpec capability 'minimumDistance' is not a query.
```

</Python>

## Run specs

<TypeScript>

`geospec run`, the command in `@taucad/geospec-engine`, runs every `*.geospec.ts` or `*.geospec.js` file under the directory it is given, with no configuration file: it compiles each spec, supplies the engine and owns the subjects, so a spec has no hooks. A spec imports `describe`, `it` and `expectGeo` from `geospec` and `loadModel` from `geospec/model`, which takes no engine and reads a path relative to that directory; it never imports `@taucad/geospec-engine`.

```ts title="plate.geospec.ts"
import { describe, expectGeo, it } from 'geospec';
import { loadModel } from 'geospec/model';

describe('plate', () => {
  it('is 40 x 40 x 20 with a 10 mm bore', async () => {
    const plate = await loadModel({ source: 'plate-with-through-bore.step', format: 'step' });
    expectGeo(plate).toHaveBoundingBox({ size: { x: 40, y: 40, z: 20 } });
    expectGeo(plate).toHaveCircularHole({ diameter: 10 });
  });

  it('refuses a hole claim on the gear mesh', async () => {
    const gear = await loadModel({ source: 'involute-gear.glb', sourceUnit: 'mm' });
    expectGeo(gear).toHaveCircularHole({ diameter: 4 });
  });
});
```

```console
$ npx geospec run .
FAIL plate.geospec.ts
  fail plate > refuses a hole claim on the gear mesh
    GEOSPEC_EVIDENCE_UNSUPPORTED: expectGeo(...).toHaveCircularHole() needs exact BRep circular-hole evidence, which this subject does not carry.
1 passed, 0 failed, 2 selected
```

The exit code is the verdict: 0 only when every selected test passed; a failed test, a refused claim, a run-level issue or an empty selection exits 1. A refused claim leaves its test `inconclusive`, counted in neither number on the last line. `--json` prints one report instead: `success`, an `accounting` block with `passed`, `failed`, `inconclusive`, `skipped` and `notRun`, and for each test its `status`, `diagnostics` and claim `reports`.

- `--file <path>`, `--include <glob>` and `--exclude <glob>` select files, `-t <regex>` selects `suite > test` names; a filtered run proves the selected scope only.
- `--workers [n]` runs a worker pool, sized to the host's CPUs without `n`.
- `--test-timeout <ms>`, `--shard-timeout <ms>` and `--matcher-wall-backstop <ms>` are wall-clock watchdogs, off by default; a timeout is no geometry verdict.
- `--bail` stops after the first failing file; `--forensic` appends timing lines.

Under Vitest, `geospec/vitest` registers the 26 matchers on `expect`. `setupGeoSpecVitest(options)` creates an assertion client from the `createGeoSpecAssertionClient` options and installs its matchers in the current file; `installGeoSpecVitest(client)` installs an existing client's, and `createGeoSpecVitestAdapter(client)` returns `{ matchers, flush }` without installing them. A matcher returns a promise, so await it. A failed or refused claim fails the test with the claim's result as its message, and a refusal fails under `.not` too.

```ts title="plate.test.ts"
import { readFile } from 'node:fs/promises';
import { afterAll, expect, it } from 'vitest';
import { createModelLoader } from 'geospec/model';
import { setupGeoSpecVitest } from 'geospec/vitest';
import { Engine } from 'geospec-engine/node';

const engine = new Engine();
const loadModel = createModelLoader({
  engine,
  readSource: async (source) => new Uint8Array(await readFile(source as string)),
});
setupGeoSpecVitest({ engine });
afterAll(async () => {
  await loadModel.dispose();
  engine.close();
});

it('refuses a hole claim on the gear mesh', async () => {
  const gear = await loadModel({ source: 'involute-gear.glb', sourceUnit: 'mm' });
  await expect(gear).toHaveCircularHole({ diameter: 4 });
});
```

`npx vitest run` reports `1 failed`; the message under the test is the result JSON, `GEOSPEC_EVIDENCE_UNSUPPORTED` first among its diagnostics.

Any other runner works with an explicit engine: a failed or refused claim throws `GeoSpecAssertionError`, failing the test with the engine's message; release the subjects in an `after` hook. `node --test plate.test.mjs` reports `fail 1`.

```ts title="plate.test.mjs"
import { readFile } from 'node:fs/promises';
import { after, test } from 'node:test';
import { expectGeo } from 'geospec';
import { createModelLoader } from 'geospec/model';
import { Engine } from 'geospec-engine/node';

const engine = new Engine();
const loadModel = createModelLoader({ engine, readSource: async (path) => new Uint8Array(await readFile(path)) });
after(async () => {
  await loadModel.dispose();
  engine.close();
});

test('a hole claim on the gear mesh is refused', async () => {
  const gear = await loadModel({ source: 'involute-gear.glb', sourceUnit: 'mm' });
  expectGeo(gear).toHaveCircularHole({ diameter: 4 });
});
```

</TypeScript>

<Python>

The wheel's pytest plugin gives each test an engine, created on its first `load_model` and closed at teardown, with `model_root` at pytest's `rootpath`; `GeoSpecAssertionError` extends `AssertionError`, so a failed or refused claim fails the test.

```python title="test_plate.py"
import pytest
from geospec import GeoSpecAssertionError, expect_geo, load_model


def test_plate():
    plate = load_model(file="plate-with-through-bore.step", format="step")
    expect_geo(plate).to_have_bounding_box(size={"x": 40, "y": 40, "z": 20})
    with pytest.raises(GeoSpecAssertionError) as raised:
        expect_geo(plate).to_have_circular_hole(diameter=12)
    assert raised.value.code == "GEOSPEC_FEATURE_MISMATCH"
```

```console
$ python -m pytest test_plate.py -q
.                                                                        [100%]
1 passed in 0.02s
```

Override the `geospec_engine_factory` fixture in `conftest.py` to set every test's `model_root` or `work_unit_budget`.

</Python>

## Engines

### initialize

<TypeScript>

Load and compile the WASM module once, before constructing an `Engine` from `geospec-engine`; the `node` entry needs no initialization.

```ts
initialize(input?: WasmInput, execution?: WasmExecution): Promise<void>
```

- **Parameters:** `input`, the module as bytes, a `Response`, a `URL` or a string, or omitted for the packaged module; `execution`, single-threaded by default.
- **Returns:** a promise resolved once the module is ready.
- **Throws:** `ProtocolError` `invalid-request` for module bytes with no initializer.

```ts
import { Engine, initialize } from 'geospec-engine';

new Engine(); // ProtocolError invalid-request: Call initialize() before using the GeoSpec WASM engine.
await initialize();
const engine = new Engine();
```

</TypeScript>

<Python>

The wheel needs no initialization: `GeoSpecEngine` sends the `initialize` request itself and exposes its answer as `protocol_version`, `registry_version`, `canonical_profile`, `capabilities` and `configuration`.

</Python>

### Engine

<TypeScript>

One engine owns its admitted subjects. The native addon, the WASM module and the wheel answer a claim with the same bytes: the plate's bounding-box result above is 532 canonical bytes, SHA-256 `57e6453a170bada5…`, from all three.

- **Parameters:** `new Engine(cacheOptions?, executionPermits?)` from `geospec-engine/node` takes an optional filesystem cache, `{ root, projectRoot }`, and a caller-inclusive CPU allocation, default one; `new Engine(execution?)` from `geospec-engine` takes the product `initialize` loaded.
- **Returns:** the engine the loaders and clients take as `engine`.
- **Throws:** after `close()`, every use throws `ProtocolError` `invalid-request`: `GeoSpec Node engine is closed.` or `GeoSpec WASM engine is closed.`

</TypeScript>

<Python>

`GeoSpecEngine` also admits bytes directly:

- `ingest_subject(primary, *, format, coordinate_system, source_unit, output_unit, ingest_options=None, resources=(), slot="subject")` admits STEP, glTF or GLB bytes in a `z-up` or `y-up` frame, with `(name, bytes)` resources and `output_unit` `mm`.
- `ingest_mesh(mesh, *, slot="subject")` admits `mesh-buffer-v1` bytes, named by `contentHash`.

```python
from pathlib import Path

with GeoSpecEngine(model_root=".") as engine:
    part = engine.ingest_subject(
        Path("plate-with-through-bore.step").read_bytes(),
        format="step", coordinate_system="z-up", source_unit="auto", output_unit="mm",
        ingest_options={"name": "part"}, slot="part",
    )
    print(part.slot, part.identity_field, part.identity[:16])  # part subjectHash a53548710335079b
```

</Python>

## Results

A root `expectGeo` matcher returns a `GeoSpecAssertion`: the claim, the engine's `report` and the load it ran on.

<auto-type-table path="../../types/geospec/runner/types.d.mts" name="GeoSpecAssertion" />

The report is the record both languages keep: the canonical claim, plan and result bytes, the `claim` with its defaults filled in, and the `result` with `status`, `diagnostics` and `evidence`. [Reproduce a result](/docs/guides/reproduce-a-result) hashes `canonicalResult` to compare runs.

<auto-type-table path="../../types/geospec/engine/client.d.mts" name="GeoSpecCanonicalClaimReport" />

In Python the same record is the frozen `GeoSpecAssertionReport`, with `canonical_*_bytes`, `claim`, `result`, `diagnostics`, `passed` and `provenance`.

A failed claim carries the matcher's mismatch code, such as `GEOSPEC_FEATURE_MISMATCH`; a refused claim carries the reason the [common refusals](/docs/reference/overview#common-refusals) list, such as `GEOSPEC_EVIDENCE_UNSUPPORTED` or `MATCHER_TIMEOUT` with the budget and the units used in `details`.

## Errors

### GeoSpecAssertionError

<TypeScript>

Thrown by every matcher for a failed or refused claim, from `geospec/assertion-client`, with `report`, `claim`, `result`, `diagnostics` and the three canonical byte fields. It has no `code`: read `report.status` for the outcome and `diagnostics[0].code` for the reason.

</TypeScript>

<Python>

Raised by every matcher for a failed or refused claim, and by `expect_geo` and `load_model` for a request the engine or host rejects. It extends `AssertionError` and adds `code` (the first diagnostic's, or the protocol code), `report`, `result`, `claim`, `diagnostics`, the `canonical_*_bytes` and `protocol_error`, the wrapped native exception.

</Python>

### GeoSpecModelLoadError

<TypeScript>

Thrown by `loadModel`, from `geospec/model`, with `diagnostics` as `GeometryDiagnostic` rows; the first one's `code` names the cause.

</TypeScript>

<Python>

Python has no separate load error: `load_model` raises `GeoSpecAssertionError`.

</Python>

### ProtocolError

Thrown by the engine for a request it does not accept, with `code` and `message`; a refused claim is a result, not an error. `geospec-engine` exports the class and the TypeScript assertions let it through; Python's `geospec_engine_native.ProtocolError` escapes `evaluate_geo` and `query_geo`, and `expect_geo` wraps it in `GeoSpecAssertionError` with the same `code`.

- `invalid-claim`: an unknown payload field, a bare-number scalar, or a subject the engine never admitted.
- `invalid-request`: a closed engine, or a WASM engine used before `initialize()`.
- `limit-exceeded`: a request over the engine's admission limits, such as its retained subject count.

## Constants

- `geoSpecMatcherNames`, from `geospec`: the 26 matcher names in registry order, `toHaveBoundingBox` first and `toSatisfyParallelPlaneDistance` last.
- `geoSpecMaximumWorkUnitLimit`, from `geospec/assertion-client`: 512,000,000, the largest `workUnitLimit` unless a host raises `maximumWorkUnitLimit`.
- Defaults: 8,000,000 work units (`configuration["defaultWorkUnitBudget"]` in Python), a tolerance of 0.02 mm and claim ids `geospec-claim-N`.
- Protocol version 3, registry version 5, canonical profile `geospec-jcs-v1` and 32 capabilities: the 26 matchers, the five queries and `minimumDistance`.
