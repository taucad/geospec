Each capability in the engine's registry has one section in this reference. The table is generated from the registry at build time; each name links to its section. The [cheat sheet](/docs/reference/cheat-sheet) lists every capability on one page.

An **assertion** answers passed, failed or refused, under either polarity. A **query** reports what the engine measured and accepts positive polarity only. **Reads faces** means the claim measures BRep faces or edges, so a STEP subject whose faces carry no surface refuses it.

## How to read a section

Every section has the same parts:

- **Signature**: the claim's `capability` and the shape of its `payload`, then the Python spelling. A third line names the TypeScript assertion form that ships inside Tau; this site documents the `geospec-engine` package, which takes the claim object.
- **Payload**: the fields, their types and defaults, and the wire payload the engine receives.
- **Admitted geometry**: which subjects the engine measures, and what it refuses.
- **Refusal codes**: the diagnostic codes of a refused result, and the code of a failed one.
- **Examples**: one claim that passes and one the engine refuses, as the TypeScript claim object and as the Python call. Each comment records the status the published package returned.

## Where a claim goes

In TypeScript and JavaScript, a claim is one entry of `plan.claims` in a `submitClaims` request. `engine.processRequest` takes the request as UTF-8 bytes and returns the result bytes; the [API reference](/docs/api) covers the engine and `evaluateClaim`, which runs one claim and returns its canonical plan, claim and result.

```ts title="submit-claims.mjs"
{
  method: 'submitClaims',
  requestId: 'volume',
  protocolVersion: 3,
  registryVersion: 5,
  canonicalProfile: 'geospec-jcs-v1',
  plan: {
    subjects: [{ slot: 'part', subjectHash }],
    claims: [
      { claimId: 'volume', capability: 'toHaveVolume', subjectSlots: ['part'], polarity: 'positive', workUnitBudget: 8000000,
        payload: { kind: 'volume', expected: { value: 30429.2, tolerance: 0.5 } } },
    ],
  },
}
```

Every field of the claim is required on the wire. `subjectSlots` names the slot the subject was bound to; the examples bind one subject to `part`. `workUnitBudget` has no wire default; `8000000` is the engine's own default, which the Python facade fills in. A mesh admitted through `ingestMesh` is named by `contentHash` instead of `subjectHash`.

In Python, `expect_geo(subject)` builds the same claim from keyword fields and sends it as one `evaluateClaim` call. The snake_case method names map to the capability names; nested field names keep their wire spelling, such as `holeDiameter`. A passed claim returns a `GeoSpecAssertionReport`; a failed or refused claim raises `GeoSpecAssertionError`. `evaluate_geo` returns the report without raising, and `query_geo` runs a query. The [Python guide](/docs/python) covers the engine, `load_model` and the pytest plugin.

## Shared payload rules

- **Units.** Lengths are millimetres, areas mm², volumes mm³, in the z-up frame the subject was admitted in.
- **Tolerance.** Where a section lists `tolerance`, equality is `abs(measured - expected) <= tolerance`. The default is `0.02` mm unless the section says otherwise.
- **Numeric expectation.** A number, or an object with any of `value`, `greaterThan`, `greaterThanOrEqual`, `lessThan` and `lessThanOrEqual`. Tolerance applies to `value` only; the four comparisons are strict as written. The object replaces the number in place, so a scalar field nests its comparators: `value: { greaterThanOrEqual: 2 }`, and `size: { x: { lessThan: 41 } }` for an axis.
- **Points.** A `[x, y, z]` triple, or an object with any of `x`, `y` and `z` to constrain only those axes.
- **Selectors.** A component or occurrence name is an exact string, or a regular expression. On the wire a regular expression is `{ type: 'regexp', pattern, flags }`; in Python it is `GeoSpecRegex(pattern, flags)`.
- **Arguments.** The Python facade sends `{ kind, arguments: [expected] }`; the engine lowers it to `{ kind, expected }` and records the lowered form in the canonical claim. A payload with both must agree.
- **Unknown fields.** A payload with an unknown or malformed field is not evaluated. `processRequest` throws a `ProtocolError` with code `invalid-claim`; Python raises `GeoSpecAssertionError` with that code.

## Common refusals

These apply to every section, so the sections do not repeat them:

- `MATCHER_TIMEOUT`: the claim used up its `workUnitBudget` and was abandoned. The engine's default budget is 8,000,000 work units.
- `GEOSPEC_EVIDENCE_UNSUPPORTED` on a capability that reads faces, when the STEP subject's faces carry no surface (tessellated-only product geometry).
- `GEOSPEC_UNSUPPORTED_EVIDENCE` on a STEP subject admitted in a y-up frame: such a subject answers `minimumDistance` only.
- `GEOSPEC_BACKEND_FAILED`: the geometry backend could not complete the measurement.

A refusal is never a pass, and negating a claim does not turn a refusal into a pass. [Read a refusal](/docs/guides/read-a-refusal) covers what to change.
