---
title: Features
description: Planar and cylindrical faces, holes, hole patterns, chamfers, fillets, wall thickness and void continuity.
---

These assertions find manufacturing features in a STEP file's exact BRep. A mesh has no surface types, so each refuses on a mesh subject. Every feature claim refuses when the engine cannot classify every face it would need: an unclassified face could be the missing feature, so a pass or a failure would be a guess.

`plate`, `box` and `gear` are the site's demo models; `coupling`, `chamferBlock`, `filletBlock` and `guide` are repository fixtures: six 5 mm holes on a 45 mm bolt circle, one 1 mm planar chamfer, one 2 mm fillet, and a valve guide with a straight bore along z in its `guide` occurrence. Python matchers are snake_case; their keywords keep the camelCase field names (`holeDiameter=`). A failed or refused call throws `GeoSpecAssertionError` in TypeScript and raises it in Python. Refusal codes add to the [common refusals](/docs/reference/overview#common-refusals).

## toHavePlanarFace

Asserts that at least one planar face lies on the declared plane.

**Signature**

<TypeScript>

```ts
expectGeo(part).toHavePlanarFace(expected: GeoSpecPlanarFaceExpectation): GeoSpecAssertion
```

</TypeScript>

<Python>

```python
expect_geo(part).to_have_planar_face(normal=..., offset=..., area=..., tolerance=...) -> GeoSpecAssertionReport
```

</Python>

**Fields**

| Field       | Type                     | Default     | Meaning                                        |
| ----------- | ------------------------ | ----------- | ---------------------------------------------- |
| `normal`    | point                    | required    | Plane normal                                   |
| `offset`    | number, mm               | required    | Signed distance from the origin along `normal` |
| `area`      | numeric expectation, mm² | not checked | Face area                                      |
| `tolerance` | number, 0 or more        | `0.02`      | Error per normal component, offset and area    |

The plane is the set of points `p` with `normal · p = offset`. A face whose outward normal points the other way matches when both the normal and the offset flip.

**Admitted geometry**

- STEP with exact BRep faces whose surface is a plane.

**Refusal codes**

- `GEOSPEC_EVIDENCE_UNSUPPORTED`: the subject carries no BRep.

A failed claim carries `GEOSPEC_FEATURE_MISMATCH`, listing every planar face it found.

**Examples**

<TypeScript>

```ts
// passed: plate, its top face is z = 20
expectGeo(plate).toHavePlanarFace({ normal: [0, 0, 1], offset: 20 });
// refused (GEOSPEC_EVIDENCE_UNSUPPORTED): gear, a GLB mesh
expectGeo(gear).toHavePlanarFace({ normal: [0, 0, 1], offset: 5 });
```

</TypeScript>

<Python>

```python
# passed: plate, its top face is z = 20
expect_geo(plate).to_have_planar_face(normal=[0, 0, 1], offset=20)
# refused (GEOSPEC_EVIDENCE_UNSUPPORTED): gear, a GLB mesh
expect_geo(gear).to_have_planar_face(normal=[0, 0, 1], offset=5)
```

</Python>

## toHaveCircularHole

Asserts that the part has a circular hole of the declared diameter.

**Signature**

<TypeScript>

```ts
expectGeo(part).toHaveCircularHole(expected: GeoSpecCircularHoleExpectation): GeoSpecAssertion
```

</TypeScript>

<Python>

```python
expect_geo(part).to_have_circular_hole(diameter=..., through=..., axis=..., center=..., tolerance=...) -> GeoSpecAssertionReport
```

</Python>

**Fields**

| Field       | Type                  | Default     | Meaning                                       |
| ----------- | --------------------- | ----------- | --------------------------------------------- |
| `diameter`  | number, 0 or more, mm | required    | Bore diameter                                 |
| `through`   | boolean               | not checked | `true` when both ends open onto outside faces |
| `axis`      | `'x'`, `'y'` or `'z'` | not checked | Bore axis                                     |
| `center`    | point                 | not checked | Centre of the bore's cylindrical face         |
| `tolerance` | number, 0 or more     | `0.02`      | Error on `diameter` and `center`              |

**Admitted geometry**

- STEP with exact BRep faces. A hole is a cylindrical bore the engine qualifies from the solid's topology: material all round it, and each end a mouth, a floor or, opposite a mouth, a counterbore shoulder. A chamfered, countersunk or rounded rim still opens the bore, and its cone or torus counts as part of that mouth. The bore may be one seamed cylinder or a band of coaxial partial cylinders that closes the full turn, which is what a sketched circle drawn as two arcs leaves. It measures diameter, axis, centre and ends, not manufacturability.
- A cross-drilled hole may pierce a bore's wall between its rims, and the bore still counts. Where a cross hole leaves a pin or a hole leaves a slope, its rim is an oblique mouth. A curved floor or a tangent hole stays undecided. An outer chamfer is an exterior cone, and a rounded corner, slot end or flute an open arc, never part of a hole.
- One qualified matching hole passes. A failure needs every bore candidate qualified: an unqualified bore could be the hole, so the claim refuses.

**Refusal codes**

- `GEOSPEC_EVIDENCE_UNSUPPORTED`: the subject carries no BRep.
- `GEOSPEC_UNSUPPORTED_EVIDENCE`: no qualified hole matches and at least one bore candidate is unqualified.

A failed claim carries `GEOSPEC_FEATURE_MISMATCH`: the plate fails `diameter: 12`.

**Examples**

<TypeScript>

```ts
// passed: plate, a 10 mm through bore along z
expectGeo(plate).toHaveCircularHole({ diameter: 10, through: true, axis: 'z' });
// refused (GEOSPEC_EVIDENCE_UNSUPPORTED): gear, a GLB mesh
expectGeo(gear).toHaveCircularHole({ diameter: 4 });
```

</TypeScript>

<Python>

```python
# passed: plate, a 10 mm through bore along z
expect_geo(plate).to_have_circular_hole(diameter=10, through=True, axis="z")
# refused (GEOSPEC_EVIDENCE_UNSUPPORTED): gear, a GLB mesh
expect_geo(gear).to_have_circular_hole(diameter=4)
```

## toHaveCircularHolePattern

Asserts that the part has a circular pattern of equal holes.

**Signature**

<TypeScript>

```ts
expectGeo(part).toHaveCircularHolePattern(expected: GeoSpecCircularHolePatternExpectation): GeoSpecAssertion
```

</TypeScript>

<Python>

```python
expect_geo(part).to_have_circular_hole_pattern(count=..., holeDiameter=..., boltCircleDiameter=..., axis=..., center=..., tolerance=...) -> GeoSpecAssertionReport
```

</Python>

**Fields**

| Field                | Type                  | Default     | Meaning                               |
| -------------------- | --------------------- | ----------- | ------------------------------------- |
| `count`              | integer, 0 or more    | required    | Holes in the pattern, matched exactly |
| `holeDiameter`       | number, 0 or more, mm | required    | Diameter of every hole                |
| `boltCircleDiameter` | number, 0 or more, mm | not checked | Bolt circle diameter                  |
| `axis`               | `'x'`, `'y'` or `'z'` | not checked | Common axis                           |
| `center`             | point                 | not checked | Bolt circle centre                    |
| `tolerance`          | number, 0 or more     | `0.02`      | Error on the diameters and the centre |

A pattern is two or more qualified holes with the same axis, diameter and ends. Holes more than 20 mm apart along the axis start a new pattern.

**Admitted geometry**

- STEP with exact BRep faces, as for `toHaveCircularHole`.
- A pattern needs the complete hole inventory, so any unqualified bore candidate refuses the claim.

**Refusal codes**

- `GEOSPEC_EVIDENCE_UNSUPPORTED`: the subject carries no BRep.
- `GEOSPEC_UNSUPPORTED_EVIDENCE`: at least one bore candidate is unqualified.

A failed claim carries `GEOSPEC_FEATURE_MISMATCH`.

**Examples**

<TypeScript>

**Fields**

| Field       | Type                  | Default     | Meaning                                            |
| ----------- | --------------------- | ----------- | -------------------------------------------------- |
| `distance`  | number, 0 or more, mm | required    | Chamfer setback                                    |
| `selection` | string                | any chamfer | The unique label the STEP source gives the chamfer |

## toHaveMinimumWallThickness

Asserts the thinnest wall of the part.

**Signature**

<TypeScript>

```ts
expectGeo(part).toHaveMinimumWallThickness(expected: GeoSpecMinimumWallThicknessExpectation): GeoSpecAssertion
```

</TypeScript>

<Python>

```python
expect_geo(part).to_have_minimum_wall_thickness(value=..., tolerance=...) -> GeoSpecAssertionReport
```

</Python>

**Fields**

| Field       | Type                    | Default  | Meaning                                                         |
| ----------- | ----------------------- | -------- | --------------------------------------------------------------- |
| `value`     | numeric expectation, mm | required | Thinnest wall; `{ greaterThanOrEqual: 2 }` states a lower limit |
| `tolerance` | number, 0 or more       | `0.02`   | Error on `value`                                                |

**Admitted geometry**

- A STEP part whose whole shape is a complete axis-aligned box or a right circular cylinder. The thickness is the exact minimum over the whole part, not a sample.
- Any other shape refuses, the bored plate included. The engine does not estimate wall thickness from samples or a mesh.

**Refusal codes**

- `GEOSPEC_EVIDENCE_UNSUPPORTED`: the subject carries no BRep, or its shape is outside the qualified box and cylinder domains.

A failed claim carries `GEOSPEC_FEATURE_MISMATCH`.

**Examples**

<TypeScript>

```ts
// passed: box, 10 × 20 × 30 mm, thinnest across x
expectGeo(box).toHaveMinimumWallThickness({ value: 10 });
// refused (GEOSPEC_EVIDENCE_UNSUPPORTED): plate, a bored plate is outside the box and cylinder domains
expectGeo(plate).toHaveMinimumWallThickness({ value: { greaterThanOrEqual: 2 } });
```

</TypeScript>


## toHaveVoidContinuity

Asserts that an open channel runs through the material along a declared path, such as a bore, duct or passage.

**Signature**

<TypeScript>

```ts
expectGeo(part).toHaveVoidContinuity(expected: GeoSpecVoidContinuityExpectation): GeoSpecAssertion
```

</TypeScript>

<Python>

```python
expect_geo(part).to_have_void_continuity(path=..., material=..., bounds=..., minCrossSection=..., isolatedFrom=...) -> GeoSpecAssertionReport
```

</Python>

**Fields**

| Field             | Type                                | Default                    | Meaning                                                                        |
| ----------------- | ----------------------------------- | -------------------------- | ------------------------------------------------------------------------------ |
| `path`            | array of points or `{ occurrence }` | required                   | Ordered waypoints in the void; `{ occurrence }` means the centre of its bounds |
| `material`        | array of occurrence names           | required unless `bounds`   | Occurrences whose solids bound the void                                        |
| `bounds`          | `{ min, max }`                      | required unless `material` | Region decided in; without it, the material bounds padded by 2 mm              |
| `minCrossSection` | number, 0 or more, mm²              | not checked                | Smallest cross-section along the path                                          |
| `isolatedFrom`    | array of points                     | `[]`                       | Points the void must not reach                                                 |

Every point must lie inside the region. The published types declare defaults for `material` and `bounds`; the engine refuses a claim with neither. The path's shape picks the route:

- Points and `bounds`: the engine follows the void through a material that is a complete box or right circular cylinder and checks each point.
- Points without `bounds`: the path must run along one straight bore in exactly one `material` occurrence, with 2 to 16 points and no `isolatedFrom`. This route passes or refuses; it never fails.
- Any `{ occurrence }` waypoint: the engine decides the path on an exact solid model of the material. `minCrossSection` refuses here, because the sections are sampled.

**Admitted geometry**

- STEP with exact BRep faces and the named material occurrences.
- A path the engine cannot decide refuses. An unresolved section does not show a blocked channel.

**Refusal codes**

- `GEOSPEC_VOID_CONTINUITY_UNSUPPORTED`: neither `material` nor `bounds`, an absent occurrence, a point outside the region, or a path outside the route's limits.
- `GEOSPEC_EVIDENCE_UNSUPPORTED`: `minCrossSection` on the occurrence route, or the subject carries no BRep.
- `GEOSPEC_UNSUPPORTED_EVIDENCE`: the material is outside the `bounds` route's box and cylinder domains, as the guide is, or the occurrence route has no exact solid model.
- `GEOSPEC_ANALYSIS_LIMIT`: the arrangement needs more than a capacity the proof profile fixes, such as 16 distinct materials, or a cell, record or exact-arithmetic capacity. `details` carry `limit` and `required`, and no host limit raises them.

A failed claim carries `GEOSPEC_VOID_CONTINUITY_MISMATCH`.

**Examples**

<TypeScript>

```ts
// passed: guide, a straight bore along z through the 'guide' occurrence
expectGeo(guide).toHaveVoidContinuity({
  material: ['guide'],
  path: [
    [0, 0, 3],
    [0, 0, 42],
  ],
});
// refused (GEOSPEC_VOID_CONTINUITY_UNSUPPORTED): gear, a GLB mesh has no 'guide' occurrence
expectGeo(gear).toHaveVoidContinuity({
  material: ['guide'],
  path: [
    [0, 0, 3],
    [0, 0, 42],
  ],
});
```

</TypeScript>

<Python>

```python
# passed: guide, a straight bore along z through the 'guide' occurrence
expect_geo(guide).to_have_void_continuity(material=["guide"], path=[[0, 0, 3], [0, 0, 42]])
# refused (GEOSPEC_VOID_CONTINUITY_UNSUPPORTED): gear, a GLB mesh has no 'guide' occurrence
expect_geo(gear).to_have_void_continuity(material=["guide"], path=[[0, 0, 3], [0, 0, 42]])
```

</Python>
