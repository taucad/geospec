---
title: Features
description: Planar and cylindrical faces, holes, hole patterns, chamfers, fillets, wall thickness and void continuity.
---

These assertions find manufacturing features in a STEP file's exact BRep. A mesh has no surface types, so each of them refuses on a mesh subject. Every feature claim refuses when the engine cannot classify all the faces it would need: an unclassified face could be the missing feature, so a pass or a failure would both be guesses.

The Python examples run inside this block. `plate`, `box` and `gear` are the site's demo models; the rest are engine fixtures: a coupling with six 5 mm holes on a 45 mm bolt circle, a block with one 1 mm planar chamfer, a block with one 2 mm fillet, and a valve guide whose `guide` occurrence has a straight bore along z.

```python title="test_features.py"
from geospec import GeoSpecEngine, expect_geo, load_model

with GeoSpecEngine(model_root=".") as engine:
    plate = load_model(file="plate-with-through-bore.step", format="step")
    box = load_model(file="box-10x20x30.step", format="step")
    gear = load_model(file="involute-gear.glb", source_unit="mm")
    coupling = load_model(file="fixtures/kernel-skill-acceptance/build123d-coupling.step", format="step")
    chamfer_block = load_model(file="fixtures/edge-treatments/01-planar-chamfer.step", format="step")
    fillet_block = load_model(file="fixtures/edge-treatments/02-cylindrical-fillet.step", format="step")
    guide = load_model(file="fixtures/nominal-bore-void/guide.step", format="step")
```

## toHavePlanarFace

Asserts that at least one planar face lies on the declared plane.

**Signature**

```ts
capability: 'toHavePlanarFace'
payload: { kind: 'planarFace', expected: { normal, offset, area?, tolerance? } }
// Python: expect_geo(part).to_have_planar_face(normal=[...], offset=..., area=...)
// Inside Tau: expectGeo(part).toHavePlanarFace(expected)
```

**Payload**

| Field       | Type                | Default     |
| ----------- | ------------------- | ----------- |
| `normal`    | point               | required    |
| `offset`    | number, mm          | required    |
| `area`      | numeric expectation | not checked |
| `tolerance` | number, 0 or more   | `0.02`      |

The plane is the set of points `p` with `normal · p = offset`. A face whose outward normal points the other way matches when both the normal and the offset flip. `tolerance` applies to each normal component, the offset and `area.value`. Wire: `{ kind: 'planarFace', expected }`.

**Admitted geometry**

- STEP with exact BRep faces whose surface is a plane.

**Refusal codes**

- `GEOSPEC_EVIDENCE_UNSUPPORTED`: the subject carries no BRep, or the kernel could not read its faces.

A failed claim carries `GEOSPEC_FEATURE_MISMATCH`, listing every planar face it found.

**Examples**

```ts title="TypeScript"
[
  // passed: plate, the 40 × 40 × 20 mm STEP plate; its top face is z = 20
  {
    claimId: 'top',
    capability: 'toHavePlanarFace',
    subjectSlots: ['part'],
    polarity: 'positive',
    workUnitBudget: 8000000,
    payload: { kind: 'planarFace', expected: { normal: [0, 0, 1], offset: 20 } },
  },
  // refused (GEOSPEC_EVIDENCE_UNSUPPORTED): gear, the ten-tooth gear, a GLB mesh
  {
    claimId: 'top-mesh',
    capability: 'toHavePlanarFace',
    subjectSlots: ['part'],
    polarity: 'positive',
    workUnitBudget: 8000000,
    payload: { kind: 'planarFace', expected: { normal: [0, 0, 1], offset: 5 } },
  },
];
// Inside Tau: expectGeo(part).toHavePlanarFace({ normal: [0, 0, 1], offset: 20 })
```

```python title="Python"
expect_geo(plate).to_have_planar_face(normal=[0, 0, 1], offset=20)  # passed
expect_geo(gear).to_have_planar_face(normal=[0, 0, 1], offset=5)  # refused (GEOSPEC_EVIDENCE_UNSUPPORTED)
```

## toHaveCylindricalFace

Asserts that at least one cylindrical face has the declared radius along the declared axis.

**Signature**

```ts
capability: 'toHaveCylindricalFace'
payload: { kind: 'cylindricalFace', expected: { radius, axis, tolerance? } }
// Python: expect_geo(part).to_have_cylindrical_face(radius=..., axis=...)
// Inside Tau: expectGeo(part).toHaveCylindricalFace(expected)
```

**Payload**

| Field       | Type                  | Default  |
| ----------- | --------------------- | -------- |
| `radius`    | number, 0 or more, mm | required |
| `axis`      | `'x'`, `'y'` or `'z'` | required |
| `tolerance` | number, 0 or more     | `0.02`   |

A face's axis is the principal axis its cylinder axis points most along. Wire: `{ kind: 'cylindricalFace', expected }`.

**Admitted geometry**

- STEP with exact BRep faces whose surface is a cylinder. The face can be a boss or a bore; the claim does not tell them apart.

**Refusal codes**

- `GEOSPEC_EVIDENCE_UNSUPPORTED`: the subject carries no BRep, or the kernel could not read its faces.

A failed claim carries `GEOSPEC_FEATURE_MISMATCH`.

**Examples**

```ts title="TypeScript"
[

  {
    claimId: 'bore-face',
    capability: 'toHaveCylindricalFace',
    subjectSlots: ['part'],
    polarity: 'positive',
    workUnitBudget: 8000000,
    payload: { kind: 'cylindricalFace', expected: { radius: 5, axis: 'z' } },
  },
  // refused (GEOSPEC_EVIDENCE_UNSUPPORTED): gear, the ten-tooth gear, a GLB mesh
  {
    claimId: 'bore-face-mesh',
    capability: 'toHaveCylindricalFace',
    subjectSlots: ['part'],
    polarity: 'positive',
    workUnitBudget: 8000000,
    payload: { kind: 'cylindricalFace', expected: { radius: 2, axis: 'z' } },
  },
];
// Inside Tau: expectGeo(part).toHaveCylindricalFace({ radius: 5, axis: 'z' })
```

```python title="Python"

```

## toHaveCircularHole

Asserts that the part has a circular hole of the declared diameter.

**Signature**

```ts
capability: 'toHaveCircularHole'
payload: { kind: 'circularHole', expected: { diameter, through?, axis?, center?, tolerance? } }
// Python: expect_geo(part).to_have_circular_hole(diameter=..., through=..., axis=...)
// Inside Tau: expectGeo(part).toHaveCircularHole(expected)
```

**Payload**

| Field       | Type                  | Default     |
| ----------- | --------------------- | ----------- |
| `diameter`  | number, 0 or more, mm | required    |
| `through`   | boolean               | not checked |
| `axis`      | `'x'`, `'y'` or `'z'` | not checked |
| `center`    | point                 | not checked |
| `tolerance` | number, 0 or more     | `0.02`      |

`center` is the centre of the hole's cylindrical face. `through` compares the ends the engine read for the bore: `true` when both open onto outside faces. Wire: `{ kind: 'circularHole', expected }`.

**Admitted geometry**

- STEP with exact BRep faces. A hole is a cylindrical bore the engine qualifies from the solid's topology: material all round it, and each end a mouth or a floor. The claim measures the bore's diameter, axis, centre and ends; it is not a manufacturability check.
- One qualified matching hole is enough to pass. A failure needs every bore candidate qualified; when one is not, the claim refuses, because the unqualified bore could be the hole.

**Refusal codes**

- `GEOSPEC_EVIDENCE_UNSUPPORTED`: the subject carries no BRep.
- `GEOSPEC_UNSUPPORTED_EVIDENCE`: no qualified hole matches and at least one bore candidate is unqualified.

A failed claim carries `GEOSPEC_FEATURE_MISMATCH`; the plate fails `diameter: 12` with "No circular hole matches diameter 12 within 0.02 mm."

**Examples**

```ts title="TypeScript"
[
  // passed: plate, the 40 × 40 × 20 mm STEP plate with a 10 mm through bore along z
  {
    claimId: 'bore',
    capability: 'toHaveCircularHole',
    subjectSlots: ['part'],
    polarity: 'positive',
    workUnitBudget: 8000000,
    payload: { kind: 'circularHole', expected: { diameter: 10, through: true, axis: 'z' } },
  },
  // refused (GEOSPEC_EVIDENCE_UNSUPPORTED): gear, the ten-tooth gear, a GLB mesh with a 4 mm centre hole
  {
    claimId: 'bore-mesh',
    capability: 'toHaveCircularHole',
    subjectSlots: ['part'],
    polarity: 'positive',
    workUnitBudget: 8000000,
    payload: { kind: 'circularHole', expected: { diameter: 4 } },
  },
];
// Inside Tau: expectGeo(part).toHaveCircularHole({ diameter: 10, through: true, axis: 'z' })
```

```python title="Python"
expect_geo(plate).to_have_circular_hole(diameter=10, through=True, axis="z")  # passed
expect_geo(gear).to_have_circular_hole(diameter=4)  # refused (GEOSPEC_EVIDENCE_UNSUPPORTED)
```

## toHaveCircularHolePattern

Asserts that the part has a circular pattern of equal holes.

**Signature**

```ts
capability: 'toHaveCircularHolePattern'
payload: { kind: 'circularHolePattern', expected: { count, holeDiameter, boltCircleDiameter?, axis?, center?, tolerance? } }
// Python: expect_geo(part).to_have_circular_hole_pattern(count=..., holeDiameter=..., boltCircleDiameter=...)
// Inside Tau: expectGeo(part).toHaveCircularHolePattern(expected)
```

**Payload**

| Field                | Type                  | Default     |
| -------------------- | --------------------- | ----------- |
| `count`              | integer, 0 or more    | required    |
| `holeDiameter`       | number, 0 or more, mm | required    |
| `boltCircleDiameter` | number, 0 or more, mm | not checked |
| `axis`               | `'x'`, `'y'` or `'z'` | not checked |
| `center`             | point                 | not checked |
| `tolerance`          | number, 0 or more     | `0.02`      |

A pattern is two or more qualified holes with the same axis, diameter and ends. Holes more than 20 mm apart along the axis start a new pattern. `count` must match exactly. Wire: `{ kind: 'circularHolePattern', expected }`.

**Admitted geometry**

- STEP with exact BRep faces, as for `toHaveCircularHole`.
- A pattern needs the complete hole inventory, so any unqualified bore candidate refuses the claim, pass or fail.

**Refusal codes**

- `GEOSPEC_EVIDENCE_UNSUPPORTED`: the subject carries no BRep.
- `GEOSPEC_UNSUPPORTED_EVIDENCE`: at least one bore candidate is unqualified.

A failed claim carries `GEOSPEC_FEATURE_MISMATCH`.

**Examples**

```ts title="TypeScript"
[
  // passed: coupling, a STEP coupling with six 5 mm holes on a 45 mm bolt circle
  {
    claimId: 'bolt-circle',
    capability: 'toHaveCircularHolePattern',
    subjectSlots: ['part'],
    polarity: 'positive',
    workUnitBudget: 8000000,
    payload: {
      kind: 'circularHolePattern',
      expected: { count: 6, holeDiameter: 5, boltCircleDiameter: 45, axis: 'z' },
    },
  },
  // refused (GEOSPEC_EVIDENCE_UNSUPPORTED): gear, the ten-tooth gear, a GLB mesh
  {
    claimId: 'bolt-circle-mesh',
    capability: 'toHaveCircularHolePattern',
    subjectSlots: ['part'],
    polarity: 'positive',
    workUnitBudget: 8000000,
    payload: { kind: 'circularHolePattern', expected: { count: 6, holeDiameter: 5 } },
  },
];
// Inside Tau: expectGeo(part).toHaveCircularHolePattern({ count: 6, holeDiameter: 5, boltCircleDiameter: 45, axis: 'z' })
```

```python title="Python"
expect_geo(coupling).to_have_circular_hole_pattern(count=6, holeDiameter=5, boltCircleDiameter=45, axis="z")  # passed
expect_geo(gear).to_have_circular_hole_pattern(count=6, holeDiameter=5)  # refused (GEOSPEC_EVIDENCE_UNSUPPORTED)
```

## toHaveChamferFeature

Asserts that the part has a chamfer of the declared distance.

**Signature**

```ts
capability: 'toHaveChamferFeature'
payload: { kind: 'chamferFeature', expected: { distance, selection?, tolerance? } }
// Python: expect_geo(part).to_have_chamfer_feature(distance=..., selection=...)
// Inside Tau: expectGeo(part).toHaveChamferFeature(expected)
```

**Payload**

| Field       | Type                  | Default     |
| ----------- | --------------------- | ----------- |
| `distance`  | number, 0 or more, mm | required    |
| `selection` | string                | any chamfer |
| `tolerance` | number, 0 or more     | `0.02`      |

`selection` names the chamfer by the unique label the STEP source gives it. Wire: `{ kind: 'chamferFeature', expected }`.

**Admitted geometry**

- STEP with exact BRep faces. A chamfer is a planar or conical face the engine qualifies between two adjacent faces, with a measured setback.
- When no qualified chamfer matches and a face's membership is unknown, or the matching chamfer has no unique label for `selection`, the claim refuses.

**Refusal codes**

- `GEOSPEC_EVIDENCE_UNSUPPORTED`: the subject carries no BRep.
- `GEOSPEC_UNSUPPORTED_EVIDENCE`: no qualified chamfer matches and a face's membership or label is unknown.

A failed claim carries `GEOSPEC_FEATURE_MISMATCH`. Its `mismatchKind` separates a wrong label (`selectorMismatch`) from a wrong distance (`geometricMismatch`).

**Examples**

```ts title="TypeScript"
[
  // passed: chamferBlock, a STEP block with a 1 mm planar chamfer
  {
    claimId: 'chamfer',
    capability: 'toHaveChamferFeature',
    subjectSlots: ['part'],
    polarity: 'positive',
    workUnitBudget: 8000000,
    payload: { kind: 'chamferFeature', expected: { distance: 1 } },
  },
  // refused (GEOSPEC_EVIDENCE_UNSUPPORTED): gear, the ten-tooth gear, a GLB mesh
  {
    claimId: 'chamfer-mesh',
    capability: 'toHaveChamferFeature',
    subjectSlots: ['part'],
    polarity: 'positive',
    workUnitBudget: 8000000,
    payload: { kind: 'chamferFeature', expected: { distance: 1 } },
  },
];
// Inside Tau: expectGeo(part).toHaveChamferFeature({ distance: 1 })
```

## toHaveMinimumWallThickness

Asserts the thinnest wall of the part.

**Signature**

```ts
capability: 'toHaveMinimumWallThickness'
payload: { kind: 'minimumWallThickness', expected: { value, tolerance? } }
// Python: expect_geo(part).to_have_minimum_wall_thickness(value=..., tolerance=...)
// Inside Tau: expectGeo(part).toHaveMinimumWallThickness(expected)
```

**Payload**

| Field       | Type                    | Default  |
| ----------- | ----------------------- | -------- |
| `value`     | numeric expectation, mm | required |
| `tolerance` | number, 0 or more       | `0.02`   |

Write `{ greaterThanOrEqual: 2 }` to state a lower limit. Wire: `{ kind: 'minimumWallThickness', expected }`.

**Admitted geometry**

- A STEP part whose whole shape is a complete axis-aligned box, or a right circular cylinder whose topology matches the engine's profile. The thickness is the exact minimum over the whole part, not a sample.
- Any other shape refuses, the bored plate included. The engine does not estimate wall thickness from samples or a mesh.

**Refusal codes**

- `GEOSPEC_EVIDENCE_UNSUPPORTED`: the subject carries no BRep, or its shape is outside the qualified box and cylinder domains.

A failed claim carries `GEOSPEC_FEATURE_MISMATCH`.

**Examples**

```ts title="TypeScript"
[
  // passed: box, the 10 × 20 × 30 mm STEP box, thinnest across x
  {
    claimId: 'wall',
    capability: 'toHaveMinimumWallThickness',
    subjectSlots: ['part'],
    polarity: 'positive',
    workUnitBudget: 8000000,
    payload: { kind: 'minimumWallThickness', expected: { value: 10 } },
  },
  // refused (GEOSPEC_EVIDENCE_UNSUPPORTED): plate, the bored plate, outside the box and cylinder domains
  {
    claimId: 'wall-plate',
    capability: 'toHaveMinimumWallThickness',
    subjectSlots: ['part'],
    polarity: 'positive',
    workUnitBudget: 8000000,
    payload: { kind: 'minimumWallThickness', expected: { value: { greaterThanOrEqual: 2 } } },
  },
];
// Inside Tau: expectGeo(part).toHaveMinimumWallThickness({ value: 10 })
```

```python title="Python"
expect_geo(box).to_have_minimum_wall_thickness(value=10)  # passed
expect_geo(plate).to_have_minimum_wall_thickness(value={"greaterThanOrEqual": 2})  # refused (GEOSPEC_EVIDENCE_UNSUPPORTED)
```

## toHaveVoidContinuity

Asserts that an open channel runs through the material along a declared path, such as a bore, duct or passage.

**Signature**

```ts
capability: 'toHaveVoidContinuity'
payload: { kind: 'voidContinuity', expected: { path, material?, minCrossSection?, isolatedFrom?, bounds? } }
// Python: expect_geo(part).to_have_void_continuity(material=[...], path=[...])
// Inside Tau: expectGeo(part).toHaveVoidContinuity(expected)
```

**Payload**

| Field             | Type                                | Default          |
| ----------------- | ----------------------------------- | ---------------- |
| `path`            | array of points or `{ occurrence }` | required         |
| `material`        | array of occurrence names           | every occurrence |
| `minCrossSection` | number, 0 or more, mm²              | not checked      |
| `isolatedFrom`    | array of points                     | `[]`             |
| `bounds`          | `{ min, max }`                      | none             |

Declare `material`, `bounds` or both: with neither, nothing bounds the void. An `{ occurrence }` waypoint stands for the centre of that occurrence's bounds. Every point must lie inside `bounds`, or inside the material's bounds padded slightly. Wire: `{ kind: 'voidContinuity', expected }`.

The path's shape picks the route the engine decides the claim on:

- Points and `bounds`: the engine follows the void through the material inside `bounds` and checks each point and each `isolatedFrom` point.
- Points without `bounds`: the path must run along one straight bore in exactly one `material` occurrence, with 2 to 16 points and no `isolatedFrom`. This route passes or refuses; it never fails.
- Any `{ occurrence }` waypoint: the engine decides the path on an exact solid model of the material. `minCrossSection` refuses on this route, because its sections are sampled.

**Admitted geometry**

- STEP with exact BRep faces and the named material occurrences.
- A path the engine cannot decide refuses. An unresolved section does not prove a blocked channel.

**Refusal codes**

- `GEOSPEC_VOID_CONTINUITY_UNSUPPORTED`: neither `material` nor `bounds` is declared, a named occurrence is absent, a point lies outside the region, or the path falls outside the route's limits.
- `GEOSPEC_EVIDENCE_UNSUPPORTED`: `minCrossSection` on the occurrence route, or the subject carries no BRep.
- `GEOSPEC_UNSUPPORTED_EVIDENCE`: the occurrence route has no exact solid model of the subject.

A failed claim carries `GEOSPEC_VOID_CONTINUITY_MISMATCH`.

**Examples**

```ts title="TypeScript"
[
  // passed: guide, a STEP valve guide whose 'guide' occurrence has a straight bore along z
  {
    claimId: 'bore-open',
    capability: 'toHaveVoidContinuity',
    subjectSlots: ['part'],
    polarity: 'positive',
    workUnitBudget: 8000000,
    payload: {
      kind: 'voidContinuity',
      expected: {
        material: ['guide'],
        path: [
          [0, 0, 3],
          [0, 0, 42],
        ],
      },
    },
  },
  // refused (GEOSPEC_VOID_CONTINUITY_UNSUPPORTED): gear, the ten-tooth gear, a GLB mesh with no 'guide' occurrence
  {
    claimId: 'bore-open-mesh',
    capability: 'toHaveVoidContinuity',
    subjectSlots: ['part'],
    polarity: 'positive',
    workUnitBudget: 8000000,
    payload: {
      kind: 'voidContinuity',
      expected: {
        material: ['guide'],
        path: [
          [0, 0, 3],
          [0, 0, 42],
        ],
      },
    },
  },
];
// Inside Tau: expectGeo(part).toHaveVoidContinuity({ material: ['guide'], path: [[0, 0, 3], [0, 0, 42]] })
```

```python title="Python"
expect_geo(guide).to_have_void_continuity(material=["guide"], path=[[0, 0, 3], [0, 0, 42]])  # passed
expect_geo(gear).to_have_void_continuity(material=["guide"], path=[[0, 0, 3], [0, 0, 42]])  # refused (GEOSPEC_VOID_CONTINUITY_UNSUPPORTED)
```
