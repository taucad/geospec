title: BRep and STEP structure
description: Shape validity, topology counts, STEP units, product structure and assembly occurrences.

These assertions read a STEP file's exact BRep and its assembly structure. A mesh carries neither, so each of them refuses on a mesh subject with `GEOSPEC_EVIDENCE_UNSUPPORTED`.

The Python examples run inside this block. `plate` and `gear` are the site's demo models; `inch_cube` and `cubes` are the engine fixtures `inch-cube.step` and `two-cube-assembly.step`, an assembly of two 10 mm cubes named `cubeA`, at the origin, and `cubeB`, centred 30 mm along x.

```python title="test_brep.py"
from geospec import GeoSpecEngine, expect_geo, load_model

with GeoSpecEngine(model_root=".") as engine:
    plate = load_model(file="plate-with-through-bore.step", format="step")
    gear = load_model(file="involute-gear.glb", source_unit="mm")
    inch_cube = load_model(file="fixtures/inch-cube.step", format="step")
    cubes = load_model(file="fixtures/two-cube-assembly.step", format="step")
```

## toBeValidBrep

Asserts that the geometry kernel reports the BRep shape valid, with optional limits on its tolerances and closure.

**Signature**

```ts
capability: 'toBeValidBrep'
payload: { kind: 'validBrep', expected: { maxTolerance?, freeBounds?, minEdgeLength?, sameParameter?, closedShells?, closedWires? } }
// Python: expect_geo(part).to_be_valid_brep(closedShells=..., maxTolerance=...)
// Inside Tau: expectGeo(part).toBeValidBrep(expected)
```

**Payload**

| Field           | Type                              | Default     |
| --------------- | --------------------------------- | ----------- |
| `maxTolerance`  | number, 0 or more                 | not checked |
| `freeBounds`    | `{ count?: numeric expectation }` | not checked |
| `minEdgeLength` | number, 0 or more                 | not checked |
| `sameParameter` | boolean                           | not checked |
| `closedShells`  | boolean                           | not checked |
| `closedWires`   | boolean                           | not checked |

The kernel's validity check always runs; the fields add limits to it. Wire: `{ kind: 'validBrep', expected }`; an empty `expected` runs the validity check alone.

**Admitted geometry**

- STEP with exact BRep faces.
- A declared limit the kernel did not measure refuses rather than passing.

**Refusal codes**

- `GEOSPEC_EVIDENCE_UNSUPPORTED`: the subject carries no BRep, or the kernel did not measure a declared limit.

A failed claim carries `GEOSPEC_FEATURE_MISMATCH`, naming each limit that failed.

**Examples**

```ts title="TypeScript"
[
  // passed: plate, the 40 × 40 × 20 mm STEP plate with a 10 mm through bore
  {
    claimId: 'valid',
    capability: 'toBeValidBrep',
    subjectSlots: ['part'],
    polarity: 'positive',
    workUnitBudget: 8000000,
    payload: { kind: 'validBrep', expected: { closedShells: true, maxTolerance: 0.01 } },
  },
  // refused (GEOSPEC_EVIDENCE_UNSUPPORTED): gear, the ten-tooth gear, a GLB mesh
  {
    claimId: 'valid-mesh',
    capability: 'toBeValidBrep',
    subjectSlots: ['part'],
    polarity: 'positive',
    workUnitBudget: 8000000,
    payload: { kind: 'validBrep', expected: {} },
  },
];
// Inside Tau: expectGeo(part).toBeValidBrep({ closedShells: true, maxTolerance: 0.01 })
```

```python title="Python"
expect_geo(plate).to_be_valid_brep(closedShells=True, maxTolerance=0.01)  # passed
expect_geo(gear).to_be_valid_brep()  # refused (GEOSPEC_EVIDENCE_UNSUPPORTED)
```

## toHaveTopologyCounts

Asserts how many vertices, edges, wires, faces, shells, solids and compounds the BRep has.

**Signature**

```ts
capability: 'toHaveTopologyCounts'
payload: { kind: 'topologyCounts', expected: { vertices?, edges?, wires?, faces?, shells?, solids?, compounds?, tolerance? } }
// Python: expect_geo(part).to_have_topology_counts(faces=..., solids=...)
// Inside Tau: expectGeo(part).toHaveTopologyCounts(expected)
```

**Payload**

| Field                                                                  | Type                | Default     |
| ---------------------------------------------------------------------- | ------------------- | ----------- |
| `vertices`, `edges`, `wires`, `faces`, `shells`, `solids`, `compounds` | numeric expectation | not checked |
| `tolerance`                                                            | number, 0 or more   | `0`         |

Wire: `{ kind: 'topologyCounts', expected }`.

**Admitted geometry**

- STEP with exact BRep faces.
- The counts are the kernel's own, by occurrence. A vertex or edge shared by several faces can be counted once per use, so a box can report more than 8 vertices; assert faces and solids when you mean the part's shape. The plate has 7 faces: six sides and the bore.

**Refusal codes**

- `GEOSPEC_EVIDENCE_UNSUPPORTED`: the subject carries no BRep.

A failed claim carries `GEOSPEC_FEATURE_MISMATCH`.

**Examples**

```ts title="TypeScript"
[
  // passed: plate, the 40 × 40 × 20 mm STEP plate with a 10 mm through bore
  {
    claimId: 'faces',
    capability: 'toHaveTopologyCounts',
    subjectSlots: ['part'],
    polarity: 'positive',
    workUnitBudget: 8000000,
    payload: { kind: 'topologyCounts', expected: { faces: 7, solids: 1 } },
  },
  // refused (GEOSPEC_EVIDENCE_UNSUPPORTED): gear, the ten-tooth gear, a GLB mesh
  {
    claimId: 'faces-mesh',
    capability: 'toHaveTopologyCounts',
    subjectSlots: ['part'],
    polarity: 'positive',
    workUnitBudget: 8000000,
    payload: { kind: 'topologyCounts', expected: { faces: 6 } },
  },
];
// Inside Tau: expectGeo(part).toHaveTopologyCounts({ faces: 7, solids: 1 })
```

```python title="Python"
expect_geo(plate).to_have_topology_counts(faces=7, solids=1)  # passed
expect_geo(gear).to_have_topology_counts(faces=6)  # refused (GEOSPEC_EVIDENCE_UNSUPPORTED)
```

## toHaveStepUnits

Asserts the length unit the STEP file declares.

**Signature**

```ts
capability: 'toHaveStepUnits'
payload: { kind: 'stepUnits', expected: { unit } }
// Python: expect_geo(part).to_have_step_units(unit=...)
// Inside Tau: expectGeo(part).toHaveStepUnits(expected)
```

**Payload**

| Field  | Type                                    | Default  |
| ------ | --------------------------------------- | -------- |
| `unit` | `'mm'`, `'cm'`, `'m'`, `'in'` or `'ft'` | required |

Wire: `{ kind: 'stepUnits', expected }`.

**Admitted geometry**

- Any STEP subject, including one whose faces carry no surface: the claim reads the file's declared unit, not its faces.
- The engine still measures every subject in millimetres; this claim checks what the file declared.

**Refusal codes**

- `GEOSPEC_EVIDENCE_UNSUPPORTED`: the subject is not a STEP file.

A failed claim carries `GEOSPEC_FEATURE_MISMATCH`.

**Examples**

```ts title="TypeScript"
[
  // passed: inchCube, a STEP cube authored in inches
  {
    claimId: 'units',
    capability: 'toHaveStepUnits',
    subjectSlots: ['part'],
    polarity: 'positive',
    workUnitBudget: 8000000,
    payload: { kind: 'stepUnits', expected: { unit: 'in' } },
  },
  // refused (GEOSPEC_EVIDENCE_UNSUPPORTED): gear, the ten-tooth gear, a GLB mesh
  {
    claimId: 'units-mesh',
    capability: 'toHaveStepUnits',
    subjectSlots: ['part'],
    polarity: 'positive',
    workUnitBudget: 8000000,
    payload: { kind: 'stepUnits', expected: { unit: 'mm' } },
  },
];
// Inside Tau: expectGeo(part).toHaveStepUnits({ unit: 'in' })
```

```python title="Python"
expect_geo(inch_cube).to_have_step_units(unit="in")  # passed
expect_geo(gear).to_have_step_units(unit="mm")  # refused (GEOSPEC_EVIDENCE_UNSUPPORTED)
```

## toHaveProductStructure

Asserts the occurrence paths of a STEP assembly and how many there are.

**Signature**

```ts
capability: 'toHaveProductStructure'
payload: { kind: 'productStructure', expected: { names?, count? } }
// Python: expect_geo(part).to_have_product_structure(names=[...], count=...)
// Inside Tau: expectGeo(part).toHaveProductStructure(expected)
```

**Payload**

| Field   | Type                | Default     |
| ------- | ------------------- | ----------- |
| `names` | array of strings    | `[]`        |
| `count` | numeric expectation | not checked |

Each name must be an occurrence path in the file. `count` is the number of occurrences; a single part with no assembly structure has none, so the plate passes `count: 0`. Wire: `{ kind: 'productStructure', expected }`.

**Admitted geometry**

- Any STEP subject. The claim reads the assembly structure only, not faces.

**Refusal codes**

- `GEOSPEC_EVIDENCE_UNSUPPORTED`: the subject is not a STEP file.

A failed claim carries `GEOSPEC_FEATURE_MISMATCH`.

**Examples**

```ts title="TypeScript"
[
  // passed: cubes, a STEP assembly of two 10 mm cubes named cubeA and cubeB
  {
    claimId: 'structure',
    capability: 'toHaveProductStructure',
    subjectSlots: ['part'],
    polarity: 'positive',
    workUnitBudget: 8000000,
    payload: { kind: 'productStructure', expected: { names: ['cubeA', 'cubeB'], count: 2 } },
  },
  // refused (GEOSPEC_EVIDENCE_UNSUPPORTED): gear, the ten-tooth gear, a GLB mesh
  {
    claimId: 'structure-mesh',
    capability: 'toHaveProductStructure',
    subjectSlots: ['part'],
    polarity: 'positive',
    workUnitBudget: 8000000,
    payload: { kind: 'productStructure', expected: { count: 2 } },
  },
];
// Inside Tau: expectGeo(part).toHaveProductStructure({ names: ['cubeA', 'cubeB'], count: 2 })
```

```python title="Python"
expect_geo(cubes).to_have_product_structure(names=["cubeA", "cubeB"], count=2)  # passed
expect_geo(gear).to_have_product_structure(count=2)  # refused (GEOSPEC_EVIDENCE_UNSUPPORTED)
```

## toHaveAssemblyOccurrences

Asserts that named occurrences exist in a STEP assembly, how many match each name, and where each match sits.

**Signature**

```ts
capability: 'toHaveAssemblyOccurrences'
payload: { kind: 'assemblyOccurrences', expected: { occurrences: [{ name, count?, bounds? }], uniqueNames? } }
// Python: expect_geo(part).to_have_assembly_occurrences(occurrences=[...], uniqueNames=...)
// Inside Tau: expectGeo(part).toHaveAssemblyOccurrences(expected)
```

**Payload**

| Field                  | Type                                           | Default            |
| ---------------------- | ---------------------------------------------- | ------------------ |
| `occurrences[].name`   | string or regular expression                   | required           |
| `occurrences[].count`  | numeric expectation                            | at least one match |
| `occurrences[].bounds` | `{ min?, max?, center?, within?, tolerance? }` | not checked        |
| `bounds.tolerance`     | number, 0 or more                              | `0.02`             |
| `uniqueNames`          | boolean                                        | `false`            |

`bounds` checks every occurrence the rule matches. `min`, `max` and `center` compare each match's box axis by axis, within `tolerance`. `bounds.within` is an occurrence path, or a regular expression over paths: each match's box must lie inside the box of at least one other occurrence that `within` names, every face widened by `tolerance`. An occurrence never counts as its own container, so a `within` that names no other occurrence fails the claim. Wire: `{ kind: 'assemblyOccurrences', expected }`.

**Admitted geometry**

- A STEP file with assembly occurrences. A file with none, such as the plate, refuses rather than reporting zero matches.
- A regular expression feature the engine cannot evaluate faithfully refuses the claim; a malformed one is an `invalid-claim` error.

**Refusal codes**

- `GEOSPEC_EVIDENCE_UNSUPPORTED`: the subject is not a STEP file, the file has no assembly occurrences, a `bounds` rule reads an occurrence without finite measured bounds, or a regular expression uses an unsupported feature.

A failed claim carries `GEOSPEC_FEATURE_MISMATCH`, listing each rule that failed.

**Examples**

```ts title="TypeScript"
[
  // passed: cubes, a STEP assembly of two 10 mm cubes, cubeB centred 30 mm along x
  {
    claimId: 'occurrences',
    capability: 'toHaveAssemblyOccurrences',
    subjectSlots: ['part'],
    polarity: 'positive',
    workUnitBudget: 8000000,
    payload: {
      kind: 'assemblyOccurrences',
      expected: {
        occurrences: [
          { name: 'cubeA', count: 1 },
          { name: 'cubeB', bounds: { min: [25, -5, -5], max: [35, 5, 5] } },
        ],
        uniqueNames: true,
      },
    },
  },
  // refused (GEOSPEC_EVIDENCE_UNSUPPORTED): plate, a single-part STEP file with no assembly occurrences
  {
    claimId: 'occurrences-part',
    capability: 'toHaveAssemblyOccurrences',
    subjectSlots: ['part'],
    polarity: 'positive',
    workUnitBudget: 8000000,
    payload: { kind: 'assemblyOccurrences', expected: { occurrences: [{ name: 'cubeA' }] } },
  },
];
// Inside Tau: expectGeo(part).toHaveAssemblyOccurrences({ occurrences: [{ name: 'cubeA', count: 1 }], uniqueNames: true })
```

```python title="Python"
expect_geo(cubes).to_have_assembly_occurrences(
    occurrences=[{"name": "cubeA", "count": 1}, {"name": "cubeB", "bounds": {"min": [25, -5, -5], "max": [35, 5, 5]}}],
    uniqueNames=True,
)  # passed
expect_geo(plate).to_have_assembly_occurrences(occurrences=[{"name": "cubeA"}])  # refused (GEOSPEC_EVIDENCE_UNSUPPORTED)
```
