---
title: Queries
description: Positive-only queries that report what the engine measured, without asserting an expected value.
---

A query reports a measurement instead of comparing it with an expectation. Queries accept positive polarity only: a negated query is an `invalid-claim` error. Read `status` before reading the evidence: a query answers `passed` with its measurement in `evidence`, `failed` when the engine ran but could not produce the measurement, with an error diagnostic naming the reason, and `refused` under the common refusals and the codes below.

In Python, `query_geo(subject, capability, payload)` returns the whole `GeoSpecAssertionReport` and raises for none of the three outcomes; `report.passed` is `True` only for `passed`. The examples run inside this block; the fixture `nist_ctc_05_asme1_ap242-e1.stp` is the NIST CTC 05 AP242 test case with semantic PMI, and `housing_shaft` is `component-interference/original.step`, a `housing` and a `shaft` that share material.

```python title="test_queries.py"
from pathlib import Path

from geospec import GeoSpecEngine, GeoSpecRegex, load_model, query_geo

with GeoSpecEngine(model_root=".") as engine:
    plate = load_model(file="plate-with-through-bore.step", format="step")
    gear = load_model(file="involute-gear.glb", source_unit="mm")
    tessellated = load_model(file="fixtures/read-profile/box-tessellated-only.step", format="step")
    cubes = load_model(file="fixtures/two-cube-assembly.step", format="step")
    housing_shaft = load_model(file="fixtures/component-interference/original.step", format="step")
    nist = load_model(file="fixtures/nist-pmi/nist_ctc_05_asme1_ap242-e1.stp", format="stp")
    y_up_plate = engine.ingest_subject(
        Path("plate-with-through-bore.step").read_bytes(),
        format="step", coordinate_system="y-up", source_unit="auto", output_unit="mm",
        ingest_options={"name": "part"},
    )
```

## analyzeBrep

Reports the exact BRep facts of a STEP subject: bounds, validity, topology counts, area, volume, centre of mass, and the planar, cylindrical, hole, chamfer and fillet inventories.

**Signature**

```ts
capability: 'analyzeBrep';
payload: null;
// Python: query_geo(part, "analyzeBrep")
// Inside Tau: client.query({ capability: 'analyzeBrep', subject })
```

**Payload**

None; the payload is `null` or omitted.

**Admitted geometry**

- STEP with exact BRep faces.
- A mesh or glTF subject has no BRep: the query answers `failed` with `GEOSPEC_BREP_EVIDENCE_UNAVAILABLE`.
- An incomplete hole or edge-treatment inventory is reported as a warning in the evidence, not hidden.

**Refusal codes**

The common refusals only. The plate's evidence reports bounds `[-20, -20, 0]` to `[20, 20, 20]`, one through hole of diameter 10 along z, and a complete bore topology.

**Examples**

```ts title="TypeScript"
[
  // passed: plate, the 40 × 40 × 20 mm STEP plate with a 10 mm through bore
  {
    claimId: 'brep',
    capability: 'analyzeBrep',
    subjectSlots: ['part'],
    polarity: 'positive',
    workUnitBudget: 8000000,
    payload: null,
  },
  // refused (GEOSPEC_EVIDENCE_UNSUPPORTED): tessellated, a STEP box whose faces carry no surface
  {
    claimId: 'brep-tessellated',
    capability: 'analyzeBrep',
    subjectSlots: ['part'],
    polarity: 'positive',
    workUnitBudget: 8000000,
    payload: null,
  },
];
```

```python title="Python"
query_geo(plate, "analyzeBrep")  # passed
query_geo(tessellated, "analyzeBrep")  # refused (GEOSPEC_EVIDENCE_UNSUPPORTED)
```

## analyzeMesh

Reports the mesh the engine measures: vertex, triangle and mesh counts, per-triangle rows, quality findings, watertightness and bounds per primitive.

**Signature**

```ts
capability: 'analyzeMesh';
payload: null;
// Python: query_geo(part, "analyzeMesh")
// Inside Tau: client.query({ capability: 'analyzeMesh', subject })
```

**Payload**

None; the payload is `null` or omitted.

**Admitted geometry**

- Mesh and glTF/GLB: the admitted triangles. The gear reports 624 triangles and a signed volume of 911.53 mm³.
- STEP: the engine's own tessellation of the subject, with its occurrences and document rows. The query reads no exact face geometry, so a STEP subject whose faces carry no surface is admitted.
- A rational plate subject has no mesh.

**Refusal codes**

- `GEOSPEC_UNSUPPORTED_EVIDENCE`: the subject has no mesh record, such as a rational plate, or was admitted in a y-up frame.

**Examples**

```ts title="TypeScript"
[
  // passed: gear, the ten-tooth gear, a GLB mesh
  {
    claimId: 'mesh',
    capability: 'analyzeMesh',
    subjectSlots: ['part'],
    polarity: 'positive',
    workUnitBudget: 8000000,
    payload: null,
  },
  // refused (GEOSPEC_UNSUPPORTED_EVIDENCE): yUpPlate, the demo plate admitted in a y-up frame
  {
    claimId: 'mesh-y-up',
    capability: 'analyzeMesh',
    subjectSlots: ['part'],
    polarity: 'positive',
    workUnitBudget: 8000000,
    payload: null,
  },
];
```

```python title="Python"
query_geo(gear, "analyzeMesh")  # passed
query_geo(y_up_plate, "analyzeMesh")  # refused (GEOSPEC_UNSUPPORTED_EVIDENCE)
```

## inspectGeometry

Resolves selectors and reports what each one matched: occurrences with bounds and centre, planes with normal and offset, axes with direction and radius.

**Signature**

```ts
capability: 'inspectGeometry'
payload: { selectors, evidence? }
// Python: query_geo(part, "inspectGeometry", {"selectors": [...]})
// Inside Tau: client.query({ capability: 'inspectGeometry', subject, payload })
```

**Payload**

| Field       | Type                                       | Default  |
| ----------- | ------------------------------------------ | -------- |
| `selectors` | array of selectors                         | required |
| `evidence`  | array of `'bounds'`, `'facts'`, `'frames'` | none     |

Selectors take the forms `toHaveSpatialRelationships` accepts. `evidence` is accepted and recorded; it does not narrow the reported fields. On the wire a regular expression is `{ type: 'regexp', pattern, flags }`.

**Admitted geometry**

- STEP: occurrences, faces, axes and planes, from the exact BRep. `{ kind: 'face', query: { surfaceType: 'cylinder' } }` on the plate reports the bore as an axis along z with radius 5.
- glTF/GLB: bodies, selected with `{ kind: 'body', of }`. Other selectors on a mesh answer `failed` with `GEOSPEC_SELECTOR_UNSUPPORTED_EVIDENCE`.
- A selector that matches nothing answers `failed` with its selector diagnostic, and an empty match list.

**Refusal codes**

The common refusals only; selector problems answer `failed`.

**Examples**

```ts title="TypeScript"
[
  // passed: cubes, a STEP assembly of two 10 mm cubes; reports cubeA at [0, 0, 0] and cubeB at [30, 0, 0]
  {
    claimId: 'inspect',
    capability: 'inspectGeometry',
    subjectSlots: ['part'],
    polarity: 'positive',
    workUnitBudget: 8000000,
    payload: {
      selectors: [{ kind: 'occurrence', name: { type: 'regexp', pattern: '.*', flags: '' }, expect: 'many' }],
    },
  },
  // refused (GEOSPEC_EVIDENCE_UNSUPPORTED): tessellated, a STEP box whose faces carry no surface
  {
    claimId: 'inspect-tessellated',
    capability: 'inspectGeometry',
    subjectSlots: ['part'],
    polarity: 'positive',
    workUnitBudget: 8000000,
    payload: { selectors: ['box'] },
  },
];
```

```python title="Python"
query_geo(cubes, "inspectGeometry", {"selectors": [{"kind": "occurrence", "name": GeoSpecRegex(".*"), "expect": "many"}]})  # passed
query_geo(tessellated, "inspectGeometry", {"selectors": ["box"]})  # refused (GEOSPEC_EVIDENCE_UNSUPPORTED)
```

## analyzeMeshOverlap

Reports the shared volume of each pair of components, without comparing it with an allowance.

**Signature**

```ts
capability: 'analyzeMeshOverlap'
payload: { pairs?, tolerance? }
// Python: query_geo(part, "analyzeMeshOverlap", {"pairs": [...]})
// Inside Tau: client.query({ capability: 'analyzeMeshOverlap', subject, payload })
```

**Payload**

| Field       | Type                                           | Default    |
| ----------- | ---------------------------------------------- | ---------- |
| `pairs`     | array of `{ left, right }` component selectors | every pair |
| `tolerance` | number, 0 or more, mm                          | `0.001`    |

Components and selectors are those of `toHaveNoComponentInterference`. `tolerance` widens the bounds check that picks candidate pairs, and its cube is the reporting cutoff: a pair whose overlap is below the cutoff is omitted.

**Admitted geometry**

- STEP: an exact Boolean intersection of each candidate pair's leaf solids, with the residual volume integrated by the geometry kernel. The evidence states that this is not an allowance check.
- glTF/GLB: a polyhedral Boolean observation over the named components. It carries no error bound, and an omitted pair is not shown to be zero.
- Fewer than two components answers `failed` with `GEOSPEC_COMPONENT_PARTITION_INCONCLUSIVE`.

**Refusal codes**

- `GEOSPEC_SELECTOR_UNMATCHED`: a `pairs` entry matches no pair of distinct components.
- `MATCHER_TIMEOUT`: the budget cannot cover one pair's Boolean work; the diagnostic names the pair.

**Examples**

```ts title="TypeScript"
[
  // passed: housingShaft, a STEP housing and shaft; reports 380.81 mm³ shared between them
  {
    claimId: 'overlap',
    capability: 'analyzeMeshOverlap',
    subjectSlots: ['part'],
    polarity: 'positive',
    workUnitBudget: 8000000,
    payload: {},
  },
  // refused (GEOSPEC_SELECTOR_UNMATCHED): housingShaft; the assembly has no 'nut' component
  {
    claimId: 'overlap-nut',
    capability: 'analyzeMeshOverlap',
    subjectSlots: ['part'],
    polarity: 'positive',
    workUnitBudget: 8000000,
    payload: { pairs: [{ left: 'housing', right: 'nut' }] },
  },
];
```

```python title="Python"
query_geo(housing_shaft, "analyzeMeshOverlap", {})  # passed
query_geo(housing_shaft, "analyzeMeshOverlap", {"pairs": [{"left": "housing", "right": "nut"}]})  # refused (GEOSPEC_SELECTOR_UNMATCHED)
```

## queryPmi

Reports the product manufacturing information (PMI) records in a STEP file, with the faces each record refers to. It reports an inventory; it does not interpret or check the tolerances.

**Signature**

```ts
capability: 'queryPmi'
payload: { maxRecords?, maxOutputBytes? }
// Python: query_geo(part, "queryPmi", {"maxRecords": ...})
// Inside Tau: client.query({ capability: 'queryPmi', subject, payload })
```

**Payload**

| Field            | Type                    | Default   |
| ---------------- | ----------------------- | --------- |
| `maxRecords`     | integer, 1 to 1,024     | `1024`    |
| `maxOutputBytes` | integer, 1 to 1,048,576 | `1048576` |

An inventory larger than either limit refuses; the engine never returns a truncated inventory. The payload may be `null`.

**Admitted geometry**

- STEP whose source is within 8 MiB. A file with no PMI, such as the plate, answers `passed` with an empty inventory.
- The query reads no face geometry, so a STEP subject whose faces carry no surface is admitted.
- A face association the engine cannot resolve uniquely is marked unavailable, with its reason.

**Refusal codes**

- `GEOSPEC_EVIDENCE_UNSUPPORTED`: the subject is not STEP, or its source exceeds 8 MiB.
- `GEOSPEC_RESOURCE_LIMIT`: the inventory exceeds `maxRecords` or `maxOutputBytes`; the NIST case refuses `maxRecords: 1`.
- `GEOSPEC_PMI_EXTRACTION_FAILED`: the PMI could not be read.

**Examples**

```ts title="TypeScript"
[
  // passed: nist, the NIST CTC 05 AP242 test case with semantic PMI
  {
    claimId: 'pmi',
    capability: 'queryPmi',
    subjectSlots: ['part'],
    polarity: 'positive',
    workUnitBudget: 8000000,
    payload: null,
  },
  // refused (GEOSPEC_EVIDENCE_UNSUPPORTED): gear, the ten-tooth gear, a GLB mesh
  {
    claimId: 'pmi-mesh',
    capability: 'queryPmi',
    subjectSlots: ['part'],
    polarity: 'positive',
    workUnitBudget: 8000000,
    payload: null,
  },
];
```

```python title="Python"
query_geo(nist, "queryPmi")  # passed
query_geo(gear, "queryPmi")  # refused (GEOSPEC_EVIDENCE_UNSUPPORTED)
```

## minimumDistance

Reports the exact minimum distance between two occurrences of a STEP assembly, with a closest point on each.

**Signature**

```ts
capability: 'minimumDistance';
payload: {
  pair: [{ occurrencePath }, { occurrencePath }];
}
// Python: no facade spelling; send the claim through geospec_engine_native.Engine
// Inside Tau: client.query({ capability: 'minimumDistance', subject, payload })
```

**Payload**

| Field                   | Type                           | Default  |
| ----------------------- | ------------------------------ | -------- |
| `pair`                  | two `{ occurrencePath }` items | required |
| `pair[].occurrencePath` | non-empty string               | required |

The two paths must differ, and each must name exactly one occurrence. A passed result's `evidence.fact` carries `distance`, `points` and `occurrences` in millimetres, z-up.

**Admitted geometry**

- An AP242 STEP subject with exact BRep faces, every length unit in millimetres.
- The one capability a STEP subject admitted in a y-up frame answers. Its points are reported in the z-up frame.
- The Python facade has no spelling for this query: `query_geo` raises `ValueError` for it. The low-level `geospec_engine_native.Engine` takes the claim as request bytes.

**Refusal codes**

- `GEOSPEC_UNSUPPORTED_EVIDENCE`: the subject is not STEP, the file is not AP242, or a length unit is not millimetres.
- `GEOSPEC_INVALID_SELECTION`: a path names no occurrence, or more than one.

**Examples**

```ts title="TypeScript"
[
  // passed: gapBoxes, a STEP assembly of two 10 mm boxes; distance 2, points [10, 0, 0] and [12, 0, 0]
  {
    claimId: 'distance',
    capability: 'minimumDistance',
    subjectSlots: ['part'],
    polarity: 'positive',
    workUnitBudget: 8000000,
    payload: { pair: [{ occurrencePath: 'subject' }, { occurrencePath: 'target' }] },
  },
  // refused (GEOSPEC_INVALID_SELECTION): gapBoxes; the assembly has no 'nut' occurrence
  {
    claimId: 'distance-nut',
    capability: 'minimumDistance',
    subjectSlots: ['part'],
    polarity: 'positive',
    workUnitBudget: 8000000,
    payload: { pair: [{ occurrencePath: 'subject' }, { occurrencePath: 'nut' }] },
  },
];
```
