---
title: Measurements
description: Bounding box, surface area, volume, mass and centre of mass.
---

These assertions measure the whole subject. A STEP subject is measured from its BRep; a mesh, from its triangles. The engine picks the evidence from the subject, and the result's evidence names the source it used (`brep` or `mesh`).

The Python examples run inside this block. `plate` and `box` are the site's demo models; `tessellated` is the engine fixture `read-profile/box-tessellated-only.step`, a STEP box whose faces carry no surface. The TypeScript examples are the same claims as `submitClaims` takes them, each against the subject its comment names, bound to slot `part`.

```python title="test_measurements.py"
from geospec import GeoSpecEngine, expect_geo, load_model

with GeoSpecEngine(model_root=".") as engine:
    plate = load_model(file="plate-with-through-bore.step", format="step")
    box = load_model(file="box-10x20x30.step", format="step")
    tessellated = load_model(file="fixtures/read-profile/box-tessellated-only.step", format="step")
```

## toHaveBoundingBox

Asserts the axis-aligned bounds of the subject.

**Signature**

```ts
capability: 'toHaveBoundingBox'
payload: { kind: 'boundingBox', expected: { min?, max?, size?, center?, tolerance? } }
// Python: expect_geo(part).to_have_bounding_box(size=..., tolerance=...) or .to_have_bounding_box(min_point, max_point)
// Inside Tau: expectGeo(part).toHaveBoundingBox(expected) or .toHaveBoundingBox(min, max)
```

**Payload**

| Field       | Type                  | Default |
| ----------- | --------------------- | ------- |
| `min`       | point of numeric axes | none    |
| `max`       | point of numeric axes | none    |
| `size`      | point of numeric axes | none    |
| `center`    | point of numeric axes | none    |
| `tolerance` | number, 0 or more     | `0.02`  |

Each axis takes a number or a numeric expectation; an omitted axis is not checked. Two positional points are shorthand for `{ min, max }`. Wire: `{ kind: 'boundingBox', expected }`.

**Admitted geometry**

- STEP: the BRep bounds.
- Mesh and glTF/GLB: the bounds of the triangle vertices. An open mesh still has bounds, so the claim passes on one triangle.

**Refusal codes**

The common refusals only. A failed claim carries `GEOSPEC_BOUNDING_BOX_MISMATCH`, naming each axis that missed. A negated claim that matches fails with `GEOSPEC_NEGATED_MATCH`, or with `GEOSPEC_NEGATED_BOUNDING_BOX_MATCH` on a `mesh-buffer-v1` subject.

**Examples**

```ts title="TypeScript"
[
  // passed: plate, the 40 × 40 × 20 mm STEP plate with a 10 mm through bore
  {
    claimId: 'size',
    capability: 'toHaveBoundingBox',
    subjectSlots: ['part'],
    polarity: 'positive',
    workUnitBudget: 8000000,
    payload: { kind: 'boundingBox', expected: { size: { x: 40, y: 40, z: 20 } } },
  },
  // refused (GEOSPEC_EVIDENCE_UNSUPPORTED): tessellated, a STEP box whose faces carry no surface
  {
    claimId: 'size-tessellated',
    capability: 'toHaveBoundingBox',
    subjectSlots: ['part'],
    polarity: 'positive',
    workUnitBudget: 8000000,
    payload: { kind: 'boundingBox', expected: { size: { x: 10, y: 20, z: 30 } } },
  },
];
// Inside Tau: expectGeo(part).toHaveBoundingBox({ size: { x: 40, y: 40, z: 20 } })
```

```python title="Python"
expect_geo(plate).to_have_bounding_box(size={"x": 40, "y": 40, "z": 20})  # passed
expect_geo(tessellated).to_have_bounding_box(size={"x": 10, "y": 20, "z": 30})  # refused (GEOSPEC_EVIDENCE_UNSUPPORTED)
```

## toHaveSurfaceArea

Asserts the total surface area of the subject.

**Signature**

```ts
capability: 'toHaveSurfaceArea'
payload: { kind: 'surfaceArea', expected: { value, tolerance? } }
// Python: expect_geo(part).to_have_surface_area(value=..., tolerance=...)
// Inside Tau: expectGeo(part).toHaveSurfaceArea(expected)
```

**Payload**

| Field       | Type                     | Default  |
| ----------- | ------------------------ | -------- |
| `value`     | numeric expectation, mm² | required |
| `tolerance` | number, 0 or more        | `0.02`   |

Wire: `{ kind: 'surfaceArea', expected }`.

**Admitted geometry**

- STEP: the BRep surface area.
- Mesh and glTF/GLB: the sum of the triangle areas. A mesh approximates curved faces, so its area differs from the BRep area of the same part.

**Refusal codes**

The common refusals only. A failed claim carries `GEOSPEC_MEASUREMENT_MISMATCH`, with the measured value and its evidence source.

**Examples**

```ts title="TypeScript"
[
  // passed: box, the 10 × 20 × 30 mm STEP box
  {
    claimId: 'area',
    capability: 'toHaveSurfaceArea',
    subjectSlots: ['part'],
    polarity: 'positive',
    workUnitBudget: 8000000,
    payload: { kind: 'surfaceArea', expected: { value: 2200 } },
  },
  // refused (GEOSPEC_EVIDENCE_UNSUPPORTED): tessellated, a STEP box whose faces carry no surface
  {
    claimId: 'area-tessellated',
    capability: 'toHaveSurfaceArea',
    subjectSlots: ['part'],
    polarity: 'positive',
    workUnitBudget: 8000000,
    payload: { kind: 'surfaceArea', expected: { value: 2200 } },
  },
];
// Inside Tau: expectGeo(part).toHaveSurfaceArea({ value: 2200 })
```

```python title="Python"
expect_geo(box).to_have_surface_area(value=2200)  # passed
expect_geo(tessellated).to_have_surface_area(value=2200)  # refused (GEOSPEC_EVIDENCE_UNSUPPORTED)
```

## toHaveVolume

Asserts the enclosed volume of the subject.

**Signature**

```ts
capability: 'toHaveVolume'
payload: { kind: 'volume', expected: { value, tolerance? } }
// Python: expect_geo(part).to_have_volume(value=..., tolerance=...)
// Inside Tau: expectGeo(part).toHaveVolume(expected)
```

**Payload**

| Field       | Type                     | Default  |
| ----------- | ------------------------ | -------- |
| `value`     | numeric expectation, mm³ | required |
| `tolerance` | number, 0 or more        | `0.02`   |

Wire: `{ kind: 'volume', expected }`.

**Admitted geometry**

- STEP: the BRep volume.
- Mesh and glTF/GLB: the absolute signed volume of the triangles. An open mesh still yields a number, so pair the claim with `toBeWatertight`.

**Refusal codes**

The common refusals only. A failed claim carries `GEOSPEC_MEASUREMENT_MISMATCH`.

**Examples**

The plate's volume is 40 × 40 × 20 minus the bore, 30,429.2 mm³ to one decimal, so the claim widens the tolerance.

```ts title="TypeScript"
[
  // passed: plate, the 40 × 40 × 20 mm STEP plate with a 10 mm through bore
  {
    claimId: 'volume',
    capability: 'toHaveVolume',
    subjectSlots: ['part'],
    polarity: 'positive',
    workUnitBudget: 8000000,
    payload: { kind: 'volume', expected: { value: 30429.2, tolerance: 0.5 } },
  },
  // refused (GEOSPEC_EVIDENCE_UNSUPPORTED): tessellated, a STEP box whose faces carry no surface
  {
    claimId: 'volume-tessellated',
    capability: 'toHaveVolume',
    subjectSlots: ['part'],
    polarity: 'positive',
    workUnitBudget: 8000000,
    payload: { kind: 'volume', expected: { value: 6000 } },
  },
];
// Inside Tau: expectGeo(part).toHaveVolume({ value: 30429.2, tolerance: 0.5 })
```

```python title="Python"
expect_geo(plate).to_have_volume(value=30429.2, tolerance=0.5)  # passed
expect_geo(tessellated).to_have_volume(value=6000)  # refused (GEOSPEC_EVIDENCE_UNSUPPORTED)
```

## toHaveMass

Asserts the mass of the subject, derived as volume × `density`.

**Signature**

```ts
capability: 'toHaveMass'
payload: { kind: 'mass', expected: { value, density?, tolerance? } }
// Python: expect_geo(part).to_have_mass(value=..., density=..., tolerance=...)
// Inside Tau: expectGeo(part).toHaveMass(expected)
```

**Payload**

| Field       | Type                | Default  |
| ----------- | ------------------- | -------- |
| `value`     | numeric expectation | required |
| `density`   | number, 0 or more   | none     |
| `tolerance` | number, 0 or more   | `0.02`   |

The mass unit follows `density`: grams per mm³ gives grams. Wire: `{ kind: 'mass', expected }`.

**Admitted geometry**

- The volume comes from the same evidence as `toHaveVolume`.
- No admitted subject carries a material mass, so a claim without `density` refuses on every subject.

**Refusal codes**

- `GEOSPEC_EVIDENCE_UNSUPPORTED`: the claim declares no `density`.

A failed claim carries `GEOSPEC_MEASUREMENT_MISMATCH`.

**Examples**

```ts title="TypeScript"
[
  // passed: box, the 10 × 20 × 30 mm STEP box in aluminium at 0.0027 g/mm³
  {
    claimId: 'mass',
    capability: 'toHaveMass',
    subjectSlots: ['part'],
    polarity: 'positive',
    workUnitBudget: 8000000,
    payload: { kind: 'mass', expected: { value: 16.2, density: 0.0027 } },
  },
  // refused (GEOSPEC_EVIDENCE_UNSUPPORTED): box, the same box with no density declared
  {
    claimId: 'mass-no-density',
    capability: 'toHaveMass',
    subjectSlots: ['part'],
    polarity: 'positive',
    workUnitBudget: 8000000,
    payload: { kind: 'mass', expected: { value: 16.2 } },
  },
];
// Inside Tau: expectGeo(part).toHaveMass({ value: 16.2, density: 0.0027 })
```

```python title="Python"
expect_geo(box).to_have_mass(value=16.2, density=0.0027)  # passed
expect_geo(box).to_have_mass(value=16.2)  # refused (GEOSPEC_EVIDENCE_UNSUPPORTED)
```

## toHaveCenterOfMass

Asserts the centre of mass of the subject, assuming uniform density.

**Signature**

```ts
capability: 'toHaveCenterOfMass'
payload: { kind: 'centerOfMass', expected: { point, tolerance? } }
// Python: expect_geo(part).to_have_center_of_mass(point=..., tolerance=...)
// Inside Tau: expectGeo(part).toHaveCenterOfMass(expected)
```

**Payload**

| Field       | Type              | Default  |
| ----------- | ----------------- | -------- |
| `point`     | point             | required |
| `tolerance` | number, 0 or more | `0.02`   |

Each declared axis is compared on its own; `{ x: 0, y: 0 }` leaves z free. Wire: `{ kind: 'centerOfMass', expected }`.

**Admitted geometry**

- STEP: the BRep centre of mass of a solid with nonzero volume.
- Mesh and glTF/GLB: the centroid of the enclosed volume. An open mesh still yields a point, so pair the claim with `toBeWatertight`.

**Refusal codes**

- `GEOSPEC_EVIDENCE_UNSUPPORTED`: the subject has no centre of mass, such as a STEP shape with zero volume.

A failed claim carries `GEOSPEC_MEASUREMENT_MISMATCH`.

**Examples**

```ts title="TypeScript"
[
  // passed: plate, the 40 × 40 × 20 mm STEP plate, centred on the z axis with z from 0 to 20
  {
    claimId: 'centre',
    capability: 'toHaveCenterOfMass',
    subjectSlots: ['part'],
    polarity: 'positive',
    workUnitBudget: 8000000,
    payload: { kind: 'centerOfMass', expected: { point: [0, 0, 10] } },
  },
  // refused (GEOSPEC_EVIDENCE_UNSUPPORTED): tessellated, a STEP box whose faces carry no surface
  {
    claimId: 'centre-tessellated',
    capability: 'toHaveCenterOfMass',
    subjectSlots: ['part'],
    polarity: 'positive',
    workUnitBudget: 8000000,
    payload: { kind: 'centerOfMass', expected: { point: [5, 10, 15] } },
  },
];
// Inside Tau: expectGeo(part).toHaveCenterOfMass({ point: [0, 0, 10] })
```

```python title="Python"
expect_geo(plate).to_have_center_of_mass(point=[0, 0, 10])  # passed
expect_geo(tessellated).to_have_center_of_mass(point=[5, 10, 15])  # refused (GEOSPEC_EVIDENCE_UNSUPPORTED)
```
